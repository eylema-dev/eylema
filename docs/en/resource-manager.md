# Bounded resource manager

G21 adds a first-party, thread-safe admission manager for three host-declared work classes: Metal, view, and model. It bounds waiting requests, active leases, and caller-declared transient bytes globally and per class. Admission reserves bytes before queueing and either commits all counters or none. Invalid, oversized, overflowing, and capacity-exhausted requests fail explicitly.

Dispatch is round-robin across classes and FIFO within a class. This avoids one busy class monopolizing available slots while keeping each class's arrival order. The default policy permits three active leases total, one per class, at most 32 queued requests total (16 per class), and at most 16 MiB of declared transient reservations (8 MiB Metal, 4 MiB view, 8 MiB model). A request can reserve at most 1 MiB. Hosts may supply smaller reviewed limits. The manager does not allocate these bytes; it accounts for the amount the caller declares. It does not observe driver allocations, VRAM, model weights, or browser memory.

A worker receives a lease and must call `check_cancelled` between bounded work chunks. Cancelling queued work removes it and releases its reservation immediately. Cancelling active work sets a cooperative token; the worker must observe that token and release the lease. A lease keeps its slot and byte reservation until it is dropped or finished. Non-cooperative platform calls cannot be preempted, cancellation is not rollback, and external effects have no exactly-once guarantee.

Tests stress simultaneous synthetic Metal/view/model reservations and concurrent admission, and print observed queue, active-lease and byte high-water marks globally and for each class. Phase barriers ensure every class reaches its queue and active-lease limits before free-running concurrent pressure; every sampled value is checked against its configured limit. They measure request-to-effective-stop latency under queued class pressure on the test host; these measurements do not establish a performance SLA. `cargo run --package eylema-runtime --example resource-proof --locked --offline` runs one native Metal addition under a Metal lease while synthetic view/model reservations remain active. This is not actual browser-view or model inference acceptance. GPU memory and model weights remain outside the manager's declared transient-byte accounting.
