# Combined GPU measurement host

G22 adds bounded measurement hosts to the existing Metal worker and three-object WebGPU scene. The native implementation remains first-party Rust; the browser host uses existing WebGPU/WGSL bindings. Evaluation orchestration and result analysis belong to eyleme-evals. Instrumentation and fixture tests alone do not establish combined hardware acceptance.

Run `cargo run --package eylema-runtime --example combined-gpu-proof --locked --offline -- 120` for a worker bounded to 120 seconds and 10,000 samples. Each call adds two 4,096-element integer arrays through the actual Metal path and checks every readback value against the exact CPU result. The worker owns a Metal resource lease, prints JSON lines, and checks stdin for `stop` between calls. The control reader accepts only `stop` followed by LF or CRLF using a fixed six-byte buffer; unknown, partial or oversized commands fail without allocating for the input length. Browser closure has no connection to its lifetime. An in-progress Metal call cannot be preempted by this cooperative stop. The reservation covers the three declared 16 KiB Metal buffers, not physical VRAM or all process memory.

Start the isolated local task service and open `/console#g22=120&trial=1` to sample 120 frames (bounded to 2–240; trial 1–3). The URL fragment stays in the browser and changes no HTTP route or authorization. The ordinary console remains unchanged without this fragment. The opt-in host redraws the same three-object scene with bounded movement and waits for each submitted queue operation to complete. Its visible JSON record preserves animation-frame intervals, submit-to-queue-completion wall durations and browser-reported JS heap estimates when available. The initial frame has no prior interval and remains null. Device loss or a failed frame retains preceding samples and records failure.

Animation-frame cadence is not a presented-frame timestamp; queue-observed wall time is not a hardware GPU timestamp. Chrome's JS heap value is an estimate and excludes driver/GPU allocations. The eval harness separately samples actual native process RSS. Physical VRAM/driver allocations, energy and model execution remain explicitly unmeasured, not zero.

A combined acceptance result must bind exact code/tree/artifact hashes, preserve three trial groups and every failed attempt, prove native call intervals overlap browser frame intervals, and observe the same native process completing further Metal calls after each view closes. Measurements describe the named M4/browser/workload profile without asserting an unapproved latency/FPS/memory SLA. Raw public records omit local paths, credentials, account identifiers and unrelated browser data.
