## Selected architecture

Share the owned decoder kernels behind private, sealed profile policies and add a typed decision API in `eylema-model`. A separately duplicated decoder would increase numerical/accounting maintenance; an arbitrary-model interpreter is outside this card. G30 public manifests, tokenizer admission, generation APIs and their context64/new-token8/work80billion limits remain intact. G23's small reference caps remain intact. A public `CpuBudget` must not acquire a path to decision-sized bounds.

The decision path owns exact manifest/layout/tokenizer admission, pair rendering, last-position head and batch normalization. Internal decoder changes separate backbone progress from output projection: G30 retains full logits, while G57 projects only the two selected embedding rows at the final committed position. Both use the same ascending-index F32 products/additions, full-domain RMS, per-head Q/K normalization, split-half absolute-position RoPE, grouped causal attention, two residuals, SwiGLU and final norm. No copied or hidden inference engine, third-party production crate, new crate/root Cargo change, schema relaxation or external fallback is introduced.

Only constructors that verify a complete immutable profile may create the larger internal policy. The model reference borrows one immutable weight snapshot and admitted tokenizer. Sequential pairs share weights and tokenizer; each pair has a fresh zero-position KV state. Model/profile/request changes cannot inherit cached activations. Any failed append poisons that pair; cancellation or failure invalidates the entire batch result. Existing declaration-only decision contracts and generic `UnsupportedLocal` assignment behavior are unchanged. Later router/harness integration remains separately gated.

## Input, rendering and typed output

Retain `decision.query-options.v1` → `decision.score-choice.v1`, `utf8-pair.v1`, `uncalibrated-score-micros.v1`, `proposal-only.v1` and `reset-per-pair.v1`. Accept one to four questions, each with one to four options, at most16pairs. Question IDs are unique per batch and option IDs unique per question, matching `[A-Za-z0-9_:.-]{1,64}`. Each question supplies instruction/query and each option supplies candidate text. Reject wrong fields/types/counts, empty identifiers and duplicate identities before model work. No caller-supplied score can masquerade as an executed result.

Proposed raw UTF8 allowance is64KiB per batch,16KiB per text field; a rendered pair is at most32KiB and all rendered pairs at most512KiB. Checked sums include repeated query/instruction bytes. Content is literal data, substituted once into the exact236byte G56 template with SHA256 `c91af212ad3548b6a9f87c8b54901bb171e2f596e7d61f666634e44fc690a637`. Preserve its exact role markers/newlines and closed empty-think assistant suffix. Reject all tokenizer-reserved role/control markers in untrusted fields. Braces or replacement-looking text never trigger another substitution. Tokenize the complete rendered prompt, preserving header/content boundary behavior established by G29. Reject oversized complete token sequences; no truncation, padding, sliding context or generated-token reservation. Since sequences are unpadded, the final token is the last nonpadding position. The manifest's reserved max-new-tokens1 does not cause a generated token.

After the full decoder succeeds, take `yes` and `no` F32 logits, widen to F64 and compute finite delta `yes-no`. Stable scalar sigmoid uses `1/(1+exp(-delta))` for nonnegative delta and `exp(delta)/(1+exp(delta))` otherwise. F64 scalar normalization is owned Rust and separately identified from F32 backbone computation. Finite deltas beyond the synthetic reference interval ±32 are allowed; evaluate the stable expression without clipping, and reject nonfinite inputs/results. ±32 remains a reference-fixture bound, not an accidental pretrained-model restriction.

Scale probability by1000000 and round half to even; enforce integer range0..1000000. As in G56, the normalized yes/no value is `score_micros >= 500000`. Rank within each question only: missing declared scores cause abstention; then equal top micros cause `tie`, top below750000 causes `below_floor`, margin below100000 causes `insufficient_margin`, otherwise choose. A single option compares against a second score of0. The threshold and margin are inclusive; no ID-based winner for a tie. Missing-score normalization is a tested arithmetic case, not a way to conceal a runtime failure.

The typed batch result binds model/source/manifest, artifact, tokenizer/config/template and request identities, per-question scores/choice/reason, actual work and logical peak. Scores expose only typed logits/delta/probability/micros and proposal semantics. Validate IDs, correspondence, finite numeric fields and counts before returning. A whole batch returns atomically: errors or cancellation discard previously completed pair proposals. Diagnostics may expose bounded numerical states for testing, never raw hidden language reasoning. Debug/ordinary evidence excludes prompt contents, raw private data and credentials.

## Context, memory, work and effective stop

Decision context is1..4096 tokens per pair, batch1 internally. Proposed maximum logical content is2560MiB and maximum aggregate work is200trillion units per request, with the existing at-most600second caller deadline. A caller may choose smaller finite budgets. These are ceilings, not performance promises. The shared aggregate counter includes admission, rendering/tokenization, zeroing, scans, backbone and head/normalization; it never resets between pairs. Preflight each known lower bound, charge actual specified work before its computation and preserve observed consumption on failure. No per-pair child may reset or widen a restrictive parent counter/deadline.

Larger attention prefixes need real computation checkpoints, not only splitting a charge before an uninterrupted loop. Max, exponential/sum, normalization and weighted-value reductions operate in ascending chunks with at most4096 charged work units between checks. Keep one maximum and sum across the entire visible prefix; never softmax independently per chunk. Retain all G30 scalar charges, plus head/rounding/output validation. Tests cover exact/one-below units and cancellation inside a long-prefix reduction. G30 results and effective-stop boundaries must remain stable through shared refactoring.

F32 KV bytes are `2*28*8*128*context*4`:939524096 at4096positions and58720256 at256. Account once for1191588280weight bytes, bounded header/layout storage,128MiB tokenizer reserve, KV, all live workspace/token/render/output capacities and conservative bookkeeping. No full-vocabulary logits workspace or context×vocabulary escaped-output reserve is needed by the two-row decision head. Sequential reset/reuse must not accumulate escaped sessions or charge a second full-weight copy. Known capacity and work arithmetic are checked before allocation; fallible allocation failure rejects. Logical bytes are not physical isolation or a measured RSS peak; report sampled RSS separately and do not double-count unified memory.

Stop/deadline checks precede admission, each rendering/tokenizer block, allocations, layer/tile and scalar blocks, selected head rows, normalization and final result publication. Cancellation after one pair but during the next must return no accepted batch and reject stale-cache reuse. Reader blocking remains a caller-supervision obligation; numerical checks do not bound an arbitrary blocked reader. Full4096forward throughput/fit is not established by a constructor or a small synthetic run.

It explicitly proposes a new G57-only owner decision; no G30 profile is automatically transferred and no G57 numerical qualification or production acceptance is self-declared. After actual written-spec/profile and concrete-plan approval, implementation tests must freeze independent tiny backbone/head vectors, all six G56 arithmetic cases, half-even/floor/margin boundary cases, finite extreme logits and malformed/output/budget/identity failures. Inject and reject wrong head IDs, wrong final position, pair-cache carryover, tile-local softmax and ignored cancellation in actual production code; restore green afterward. Preserve G23/G28/G29/G30 checks. A stop flag set before computation is insufficient evidence of effective stop.

For actual pinned-weight acceptance, propose a standalone first-party **development-only Rust F64 oracle**, with a bounded safetensors reader, layer-major full-prefix scheduling and independently implemented RMS/RoPE/GQA/attention/MLP/selected head. It imports no product kernels or inference framework, is not linked into production and requires an explicit tooling inventory entry. Decimal80 supplies independent scalar/reference checks, including tiny oracle-validation fixtures before real use. Record source/input/output digests, compiler and environment; compute references once before candidate execution. Compare finite per-layer states and both head logits with frozen per-value bound `abs(candidate-reference) <= .001 + .0002*abs(reference)`; compare scalar normalization of the *same fixed logits* to Decimal80 within1e-6 and at most1micro unit. Different computed logits may change rounded micros near a boundary; report that difference rather than alter thresholds. Candidate choice must exactly follow its own validated micros.

The concrete plan must freeze a tiny actual EN/TR two-question/two-option set with relevant and irrelevant candidates, token IDs, expected reference ordering and bounded smoke-quality criteria before the candidate sees outcomes. Keep the authored G56 prompt; do not tune it or choose a successful example after a failed run. Reference agreement alone proves arithmetic, not usefulness or Turkish competence. Full task/domain quality, calibration, GPU, training and general decision competence remain unaccepted; a failure of the frozen smoke criterion remains a failure.

The later plan must request exact finite artifact/small-file acquisition, storage/time/attempt and oracle/candidate process limits from the human before any such job. This specification grants none. Its intended acceptance sequence includes independent real reference, two-question batching, pair-order/reset correlation, malformed/context/resident preflight and effective mid-compute cancellation. Record failed attempts as well as successes. Require full exact local repository/native gates, current hosted CI, genuine separate review of final source/catalog/guide heads and measured receipts, exact reviewed/main tree correlation and main CI. Only then use existing conditional merge authority.
