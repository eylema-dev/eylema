# Runtime recovery — G13

`eylema-host` composes the owned runtime, journal, contracts and platform. Production Cargo dependencies remain first-party workspace packages; runtime/journal continue to depend toward contracts, with no browser/provider/network integration. The durable facade exposes scoped opaque enrollment and typed operations without a mutable runtime escape. The embedded caller supplies the trusted journal and HostServices. Public HTTP/CLI composition is G14/G15; this crate supplies neither person login nor request authentication.

## Durable operations and replay

A fresh journal receives host configuration version 1 and the original runtime limits. Each mutating operation writes a synchronized intent with a consecutive attempt number, executes the owned runtime, then writes a synchronized commit containing its exact outcome, ordered clock/ID/hash service transcript and semantic state fingerprint. Successful operation responses follow the commit. Known runtime errors are also committed and replayed accurately; foreign owner/session handles fail before an intent. Approval, revocation, governance, policy, delegation and cancellation follow the same rule. Authorized typed decision returns are captured from their operation and released after commit; they preserve the original permission contract, including actors with Approve/Govern permission and no Observe permission. The bounded transient return cache carries no independent authority.

Replay reconstructs confirmed owned memory with the original observed timestamps, reserved IDs and known service errors. Recorded successful SHA calls are checked with the current standard host SHA provider. Every operation's outcome and complete sectioned canonical state digest must match. Digest sections include limits/charges, grants and retired/revoked/human slots, accepted oversight, approvals/governance/policy history, tasks/leases/revisions/values/budgets, execution drafts and remaining IDs, FIFO queue, principal/operation/resource/key idempotency, plans, events, observations and globally reserved event IDs. Opaque process identities are excluded; stable slot identities are included. This is standard host SHA over canonical chunks, not a new cryptographic implementation or authentication scheme. Semantic format changes require a new compatibility version; no automatic migration is supplied.

Completed results, partial known effects, Task/Execution/Event/Evidence identities, revisions, correlated errors and observations remain exact. An identical retained admission returns its existing execution; changed canonical content conflicts. Reconstructing deterministic owned memory does not invoke an external adapter or repeat an external effect. No external exactly-once guarantee is established.

## Interrupted work and fresh authority

An intent without a validated commit is never automatically executed. Its attempt number appears in `RecoveryReport.abandoned_attempt`. Opening conservatively moves every unfinished execution to terminal `OutcomeUnknown`, retains its last confirmed value/applied effects and idempotency record, and emits an observed recovery event using the previously reserved terminal ID. If the abandoned command was the first FIFO step, its next action receives an `Unknown` effect without invented evidence. A pending cancellation does not become a fabricated effective stop. Already terminal success/failure/cancellation/unknown records are unchanged. The synchronized recovery marker binds the abandoned attempt, exact recovery outcome/transcript and digest before the opened host is exposed; a second restart preserves those results/events.

Historical grants, approval issuers, governance and human attestations reconstruct audit history inside privileged replay. Recovery retires old enrollment slots and clears human availability. Retirement is an epoch boundary, not a forged human revocation. Old opaque handles are rejected; the host must enroll anew and independently verify a person before fresh human enrollment. Stored principal strings, serialized slot numbers and old human flags cannot supply a usable new credential. Required intervention fails closed until a fresh capable controller exists. Old approval/governance issuers remain retired; a historical governance-bound task can remain unavailable rather than silently acquiring a new issuer. Accepted immutable oversight and policy/revocation history cannot be removed by reopening or request omission. Fresh grants must still obey scope/policy/operation checks; the host remains responsible for their real provenance.

A write/flush/synchronization or post-intent provider/encoding failure supplies no successful response and poisons the facade; subsequent reads/mutations fail with `Poisoned`. Close and inspected reopen are required. Complete commit bytes can remain after failed synchronization; validated reopening may retain the committed result, but it does not reconstruct the failed caller's acknowledgement. Torn/corrupt/incompatible journal bytes and invalid semantic records, gaps, transcripts, results or fingerprints fail explicitly without repair or automatic truncation. Fresh recovery-clock failure changes no bytes. Physical power loss and hostile same-user mutation remain outside the accepted proof.

## Bounds and host configuration

Intent/command envelopes are at most 64 KiB; commit/recovery envelopes at most 256 KiB; ordered operation transcripts at most 2048 calls. The current bounded runtime operation set remains below that transcript limit. Normal mutation preflights three journal envelopes: intent, worst-case commit and one spare recovery envelope. This checks record/payload/file budgets, not available physical disk capacity; actual IO failures remain possible. Append repeats its own checks. Recovery preflights its single worst-case envelope. Journal and codec limits also apply. Each semantic digest chunk uses at most the platform's 4 MiB SHA input; retained collections remain bounded by the recorded runtime limits. These are structural bounds, not measured allocator memory, latency or performance guarantees. Full-history replay/fingerprint work is finite and can be expensive; no compaction/rotation/history erasure is hidden.

Runtime sessions remain finite retained enrollment slots, including retired historical slots. Repeated restarts/new enrollment can exhaust that declared limit. Journal history is also finite; lack of recovery capacity fails explicitly. Increasing a trusted journal bound does not modify recorded runtime limits or erase history. Production host paths are configured by the embedding application in an owner-controlled directory, with G12 cooperative exclusive ownership and native 0600 creation. The proof's disposable directories use 0700. Application Support default selection, listener lifecycle and request boundaries remain G14/G15. Ordinary records are for operation/audit data. Credentials, raw private training records and hidden model reasoning must not be supplied as ordinary task data; no automatic secret classifier is claimed. Operators must protect the trusted store and must not publish its contents.

## Executed evidence

On macOS 27.0.1 ARM64 / M4 Pro / 24 GiB, Rust 1.99.0: fourteen host recovery regressions, two pure runtime recovery regressions and one journal transaction-capacity regression passed. They cover repeated exact restoration/idempotency, partial/unknown work, intent/commit synchronization failures and retained-versus-lost bytes, no response/read from poisoned state, expired epoch/foreign handles, approval/revocation/oversight/governance/policy/delegation history, cancellation receipt/effective/late results, narrow Approve/Govern decision permissions, changed payloads, recorded/fresh clock failures, capacity-before-intent and spare recovery, and invalid version/gap/transcript/outcome/digest without writes. Fault-storage snapshots simulate lost bytes; they are not physical disk observations.

`cargo run --package eylema-host --example recovery-proof --locked --offline` passed using actual macOS files/locks, file+parent+F_FULLFSYNC, CommonCrypto SHA, Security entropy and SystemTime. Four separately spawned children exit abruptly with code 86 before intent, after synchronized intent, after owned effect/before commit, and after synchronized commit/before response. Recovery retains value 2/unknown for the first three and value 5/success for the last; confirmed effects are not repeated, admission returns the same execution, all evidence resolves, and a second restart preserves exact results/events. This is actual process interruption and restart; it is not an OS crash or power cut. Enrollment is a trusted-host fixture, not real person authentication.
