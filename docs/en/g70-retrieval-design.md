# G70 project-scoped retrieval design

Status: written specification for owner review; no retrieval production code or numerical trial has been written. This is an architectural task under issue [77](https://github.com/eyleme-dev/eyleme/issues/77), proposed G70/r3. [Turkish companion](../tr/g70-retrieval-design.md).

## 1. Intent, base and scope

Build a bounded local retrieval foundation for private RAG: authorized ingestion, reproducible chunks, exhaustive vector/lexical/hybrid search, durable reopen and source-linked results. Retrieval never grants permission to act, train, publish or export. G68/G63/G13 are accepted dependencies; G87 supplies existing source/handoff patterns. Core base is `9324207e68782de8b6c892a36a175fb1701c41a9`; guide base is `0efbe545b080b2da2ac3febe021b55fd88d6726f`. Refresh both before the implementation plan activates.

Proposed implementation paths are the owned retrieval crate, the native host adapter and its tests, paired evidence documents and reviewed translation fingerprints. Root Cargo.toml/Cargo.lock must explicitly join the scope to register the new first-party crate; they are absent from G70/r2. Existing host Cargo metadata is inside the host path. No external crate, database, inference engine, platform/contract wire change or shared checker weakening is proposed. The application/HTTP/UI surface stays unchanged in this first library/native proof. Final guide card, action-plan and merged-core pin are a separate scoped delivery.

The approved approach is an exhaustive scan plus a small lexical branch, with deterministic hybrid ranking. An ANN graph would add approximate-recall/state proofs and remains future scope. External database engines conflict with current production policy. No scope/qualification record self-authorizes implementation.

## 2. Components and representation identity

The new owned Rust crate provides validated index values, UTF8 chunking, bounded scoring, canonical snapshot encoding and journal replay. It depends only on owned contracts/journal components; the host owns standard hashing, paths, native storage, current data authority and clock observations. Raw library values/serialized bytes are not security capabilities. The host exposes opaque handles with count-only Debug, not raw stored payload access.

A representation binding includes the existing semantic space ID/model/preprocessing/revision/dimensions plus nonzero manifest, artifact, tokenizer and preprocessing fingerprints. It also binds chunking and scoring profile versions. Equal dimensions do not imply compatibility. Query, every chunk and reopened index must match the whole binding. Any changed binding requires an explicitly built new index; there is no relabeling, mixed-space merge, fallback, automatic download or model activation. Host-supplied vectors are declared inputs, not authenticated proof that a model ran. G68's actual embedding execution stays separate; G70 acceptance uses synthetic vectors only.

## 3. Authorized build, reopen and search

The native adapter binds an index to one live ProjectStore identity and its project. A narrow crate-private owner-checked binding accessor may be added inside the existing host project-data module; it must call the current sealed-owner guard and expose no new public grant. Same-looking project/record/digest values from another store do not reproduce that binding. Reopening the backing store invalidates old handles/sessions; explicit index reopen and fresh host enrollment are required.

Build requires a current Collect session for each input source and all its G63 ancestry. Read through ProjectStore; retain the source DataRef and synchronized put-frame digest, not an unverified standalone digest. Source content is immutable; replacement uses a new DataRef and explicit new generation. Index data are private derivatives and carry no independent egress/training permission. The index has no export API. Its controlled file path is trusted host configuration, never derived from logical IDs or requests.

Search requires a current Execute session and a nonempty explicit allowlist of at most 16 source references. Authorize all requested references before exposing whether they are indexed, counting candidates or scoring private chunks. If any requested source is unavailable/denied, the entire request fails without partial results. Unrequested documents contribute neither vectors nor lexical scores/counts. Recheck source put digests, live store identity, session, ancestry and expiry after staging results, against one common final persisted trusted-time observation using the existing G87 pattern. Changed policy is governed by current G63 authorization, never a cached leaf flag. No durable permission receipts or cached query bodies are introduced.

Owner-controlled reopen parses bounded private history but exposes no historical generation. Before returning a usable handle, it requires fresh Execute authority for every current snapshot source and compares authorized source bytes with stored chunk coverage/text. If any current source is unavailable or changed, reopen fails; the owner must explicitly rebuild from eligible sources rather than silently salvage an older snapshot. Historical generations are structurally validated, not reauthorized for output. Search authority is checked anew; parsing a journal is not a grant. An empty snapshot is valid (zero sources/chunks), including after deleting the last source; its owner/store binding is still mandatory. A deleted source disappears from the new complete snapshot. A withdrawn/expired source fails current use even if its old bytes remain in history. Explicit expected-generation matching rejects stale handles/requests. Updating data, model or chunk profiles never silently reuses an older vector space.

## 4. Chunking and lexical profile

Read one nonempty UTF8 source of at most 8192 bytes. Reject oversized extent before scanning. Within the bounded source, reject malformed UTF8 and control characters except tab, carriage return and newline. Split into consecutive nonoverlapping windows of at most 1024 bytes, backing each boundary to a Unicode scalar boundary. Never split a scalar, skip bytes or truncate the document; empty chunks are invalid. Each chunk retains source reference/put digest, exact byte range, text hash, index generation and whole representation binding. Deterministic chunk identity is the source/range/profile tuple, not a filesystem path. The joint source/chunk limits can reject otherwise individually valid documents.

This is byte chunking, not a token estimate. No tokenizer/model call occurs in G70. A requested token ceiling returns TokenCounterUnavailable; no whitespace count or unknown-as-zero value. A later accepted embedding adapter must count its full prefix/text/special tokens and reject incompatibility before inference. G70 does not promise every chunk fits an arbitrary model context.

Lexical terms are maximal original Unicode alphanumeric runs, each lowercased with pinned Rust1.99 Unicode tables. Bind that normalization profile; do not claim locale-aware Turkish equivalence, NFC normalization, stemming or semantic quality. Lowercasing expansions stay inside the same term. Reject an oversized term rather than silently shortening it. Store unique sorted terms; repeated terms do not add frequency weight. Query limits are 2048 UTF8 bytes/32 unique terms, chunk limit 128 unique terms, and each normalized term at most 64 UTF8 bytes. Punctuation-only text yields an empty lexical set: lexical/hybrid queries reject an empty query set; a chunk with no terms has lexical score zero.

## 5. Scoring and deterministic ties

Modes are explicit: vector, lexical or hybrid. Vector/hybrid require one finite query vector with exactly the bound dimensions. Every stored/query F32 vector must have F64-computed unit-norm error at most 1e-5; zero/nonfinite/mismatched vectors reject, never silently normalize. Accumulate the scalar dot product in fixed dimension order with F64. Reject a raw dot magnitude above 1.00003; clamp only the admitted unit-norm rounding fringe to [-1,1], then round to signed millionths using nearest ties-to-even. Exhaustive scan means every eligible chunk is examined; it does not mean mathematically exact floating arithmetic or a performance guarantee.

Lexical score is set Jaccard intersection/union, zero for an empty chunk set, converted to millionths with checked integer quotient/remainder and ties-to-even. Hybrid uses an explicit integer vector weight in 1..999999 of 1000000; combine signed vector and nonnegative lexical millionths with checked wide-integer arithmetic and the same signed ties-to-even rule. Pure modes are distinct; no hidden mode switch, learned router or relevance probability. For integer division, compare twice the absolute remainder with the positive denominator; an exact half increments only an odd absolute quotient, then restore the sign. The plan freezes independent scalar/tie literals for these rules before code.

Sort descending by the final integer score, with source ASCII ID and byte offset only for stable presentation within equal-score groups. Equal scores never imply a unique winner. Request top_k 1..16 and max_hits 1..32 with top_k <= max_hits; include the full group tied at the cutoff. If the whole cutoff group exceeds max_hits, fail rather than silently break a tie. Results retain scores, mode, space, generation, source digest and exact chunk offsets. Maximum serialized result is 65536 bytes including provenance; stage and validate the whole response before returning.

## 6. Durable snapshots and failure

Use a separate owned EYLJ journal with a G70 retrieval-snapshot payload tag/version1; do not change task/G63/EYL/EYLJ formats. Every record is a complete canonical snapshot, including project, full representation binding, positive generation, ordered sources/chunks, UTF8 text/term data, little-endian F32 vector byte strings and their lineage. Codec Float support is unnecessary. Unknown fields/version, invalid finite values, duplicates, inconsistent ranges/terms, wrong project/space, digest/sequence/chain corruption or nonmonotonic generations reject. Recompute stored text/term/range invariants on replay; a checksum is not semantic validation or a MAC.

Fully stage/validate/admit the new snapshot and current source permissions before append. A generation becomes live only after the existing journal's complete synchronization and a common current authority/expiry check at acknowledgement. IO uncertainty or a post-write authorization failure gives no success receipt and requires explicit reopen; a complete but unacknowledged snapshot may exist. No automatic retry, repair, truncate, old-generation fallback or claim of a cross-journal transaction. Corrupt/torn trailing records fail closed. Source withdrawal/delete does not compact, encrypt, erase backups or recall already returned bytes. Trusted directory ownership, cooperative locks/hash/clock and same-user filesystem limits remain the existing native boundary.

## 7. Finite structural budgets

| Resource | Proposed ceiling |
|---|---|
| Sources / source text | 16 / 8192 bytes each |
| Chunks / chunk text | 128 / 1024 bytes each |
| Vector dimensions | 1..4096; selected G68 binding is 1024 |
| Query text / terms / normalized term | 2048 bytes /32 /64 bytes |
| Query requested sources / cutoff / total hits | 16 /16 /32 |
| Serialized response | 65536 bytes with provenance |
| Snapshot / generations / index file | 1 MiB /4 complete records /5 MiB |
| Logical owned retrieval residency | 64 MiB, including replay/staging copies and encoded response |
| Cooperative operation work / deadline | 100000000 charged units /30 seconds |

These are joint hard admission ceilings, not a guarantee every maximum combination fits. For example, high-dimensional vectors can exhaust snapshot bytes before 128 chunks. Checked size/work preflight precedes allocation, history read, token/term scan and scoring where extents are known; meter remaining scans/operations and check cancellation/deadline at bounded intervals. Charge each scanned, copied, encoded or hashed byte, each vector scalar multiply/add, each visited Unicode scalar and each compared term byte before that unit; checked cumulative arithmetic never wraps. These declared units are not CPU instructions. Exclude no replay/staging copy from the declared logical accounting. Caller-held G63 data, allocator slack/metadata, OS buffers and physical RSS are separately reported; 64 MiB is not a process hard-memory sandbox. Existing journal IO attempts are bounded but a native filesystem call is not a hard real-time primitive. Cancel/timeout returns no partial result and no acknowledged partial generation. Read-only search cancellation need not invalidate an otherwise healthy index; uncertain writes require reopen.

## 8. Acceptance and independent expectations

Freeze small public synthetic sources, unit vectors, lexical sets and literal expected ranks before implementation. Compare F64 scalar/rounding values to independently derived high-precision or exact rational references, including sign/half-even edges, opposite/orthogonal vectors and ties. F64 dot/norm scalars must differ from independently derived references by at most 2e-12; integer micro-score, ordering and tie expectations are exact. Include representable dot-to-micro ties: 1/128 -> 7812, 3/128 -> 23438, and their sign-symmetric negatives. Jaccard 1/128 and 3/128 use the same positive expectations. Freeze full vector/term fixtures and independent derivations in the plan; do not adjust thresholds or expected values after a failure. Require recall@k = 1.0 on fixed synthetic relevance sets with at most k relevant chunks, together with literal complete rankings/tie groups for each mode. This demonstrates deterministic implementation behavior, not model relevance or Turkish quality.

Required native tests cover actual indexing/query/close/reopen/update/delete, retained source/range/profile lineage, vector/lexical/hybrid agreement, cross-project/store/session denial before private status, revoked/changed ancestry, source/session expiry during staging and synchronization, stale generations, mixed spaces, invalid unit vectors/UTF8/terms, corrupt/torn/unknown snapshots, failed IO/sync, limits, cancellation and atomic response rejection. Include one real private temporary-file test through existing native storage and synthetic content; injected faults are not physical power loss. Existing G63/G87/G68 tests must retain their meaning. Run canonical local Python/repository/PR/diff gates and full owned Rust fmt/clippy/native tests/build plus selected portable Wasm compilation; no new target-execution claim. Current final-head CI, genuine separate owner-qualified review, authorized merge/main tree and main CI are separate gates, followed by guide proof.
