# Decision evidence and measured owned cycles

G50 adds immutable submitted alternatives and sealed actual tool snapshots. [Typed tools](typed-tools.md) retain actual G10/G11/G13 authority, stop and recovery; [project data](project-data.md) retains five separate purposes. This is a native owned read/add driver, not a model, general agent loop, graph engine or causal explanation.

## Submission and provenance

A declaration contains1–8 unique routes for the same action and score units, one selected action/tool profile/revision, constraint assertions, optional exact declared model profile/artifact/revision and uncalibrated or declared calibration-reference status. Utility integers are bounded to±1,000,000,000; declared probability basis points to0–10,000. Integer units cannot encode NaN/infinity. Rejected constraint declarations cannot be selected. Confidence, calibration references and model artifacts remain unverified submissions; no model executes here and attribution never establishes causation.

Only the original sealed admission session can attach a declaration, before its first actual step. Matching action/profile/revision is required; changed bindings or late attachment reject. Actual scoped report/source authorization is checked before attachment and each evidence read. A read-only observer cannot author the choice. Identical preexisting declarations and execution replays retain original samples. Tool reports supply actual task/execution/action/evidence associations and pending/completed/failed/stopped/partial/unknown distinctions; caller-supplied outcome objects are never accepted. The fixed implementation pin is `owned:typed-tool-driver:v1`; this pins the executed deterministic driver, not an unexecuted G46 model-loop controller.

All retained inputs constrain egress through G54's current source/session/ancestry checks. The decision snapshot is transient local Execute evidence. No automatic collection, training, external disclosure or ecosystem export occurs; those permissions remain separate. Eligible nonsecret identifiers and declared metadata, trusted ingestion and a dedicated private journal remain prerequisites. Already returned snapshots cannot be recalled; aggregation over them is a local calculation and creates no persistence/sharing grant. Fresh-only typed provenance remains: recovery cannot relabel missing lineage as literal or resume unknown effects.

## Measurements and limits

Actual standard-library monotonic observations cover admission, up to9 action/stop steps, admission-to-terminal duration including client gaps, and accepted cancellation-request-to-terminal-stop duration. Successful idempotent replay never adds another sample. Source-denied calls are excluded; failed/partial/cancelled outcomes cannot enter a completed-cycle distribution. At most128 executions are retained with no eviction.

The first newly admitted facade execution is a first/cold host call; later calls are warm/repeat host calls. This does not measure process startup, unloaded weights, cache eviction or model warm-up. A distribution accepts2–128 distinct completed snapshots from one live facade, with the same actual handler/profile/revision/payload/action-byte budgets; requires its first call and at least one repeat. Different hosts, inputs, duplicates, unfinished or stop outcomes reject. Warm raw samples are retained; nearest-rankp50/p95/p99 use sorted repeats. Successful cycles/second divides completed count by the actual earliest-admission-to-latest-terminal wall span, including inter-call gaps. It is a serial observed rate, not a concurrency capacity or SLA. Task IDs, storage growth, ambient load and authorization/client work can still affect times; the key does not prove hardware equivalence or a controlled comparison against another implementation.

The declared task payload-byte ceiling is exposed separately. Resource reservations, physical process RSS and physical VRAM are explicitly unavailable (`None`), not zero and not inferred from payload/wire budgets. G21 resource accounting and G18/G22 hardware records remain separate evidence; this counter workload cannot calibrate model memory or GPU costs.

## Validation

Portable negative tests cover empty/duplicate/over8/missing/rejected selections, score bounds and unverified calibration/model/causal status. Native tests cover actual scoped choice-to-read/add observations, revision mismatch, read-only author denial, rebinding/late attachment, original replay timings, source withdrawal and denied readers. Actual64 serial counter cycles verify64 outputs and63 repeat samples, explicit nearest ranks and positive measured rate. An actual scoped stop after one confirmed effect records partial outcome and stop latency, excluded from completed distributions. Known counters verify effects; the duration assertions have no flaky absolute speed threshold.

ARM64 macOS/Rust1.99.0 is the local target. Memory journals and existing simulated host-human authority are used; no new physical IO, real-person login, GPU/model/training/provider/G40 trial or engine/dependency is supplied. Current full gates, exact-head CI and genuine separate review remain required before acceptance. UI integration, persistent decision datasets, actual model-loop execution and performance comparisons retain later gates.
