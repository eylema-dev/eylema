# Local device-owner authorization — G73

G73 adds an owned Rust path from an actual macOS LocalAuthentication result to the existing scoped human oversight API. Native code and regression tests are implemented. **Real maintainer authentication and the bounded native approval/stop/reopen acceptance passed** on 14 October 2026; this evidence is scoped to the known counter demonstration. A capability preflight returned available on the primary Apple M4 Pro/24 GiB macOS27.0.1 ARM64; availability does not authenticate a person. General model jobs, remote identity and training acceptance are separate.

## Proof, scope and lifetime

`HumanEnrollment` is immutable, non-Clone and nonserializable. The trusted owner issues it for the current live host, exact canonical grant/scope/policy, random OS nonce and deadline. Two shown purposes are supported: `state:cli` for stop, and `state:g73-proof` for the known approval/stop demonstration. They are exact logical IDs, not paths or wildcard access. A request requires Read and RequestCancellation, only allows the declared six local permissions, and denies policy administration; the CLI purpose cannot grant ApproveAction. This registration does not grant project-data Collect/Train/external disclosure/ecosystem export.

A fresh `LAContext` evaluates deviceOwnerAuthentication through macOS's own interface, using biometry or account password as OS policy permits. Eylema supplies no credentials and sets no authentication-reuse allowance. Fixed nonempty reasons describe the supported scope; arbitrary prompts cannot substitute for proof. A callback success yields an opaque, single-use `DeviceOwnerProof` bound to the challenge and the actually shown fixed purpose; the consuming host verifies both. False/duplicate/late reply, missing capability, cancellation or timeout cannot promote it. NSError text, account names, passwords and biometric data are neither read nor retained.

Reply wait is at most60s, request use120s, proof use15s. The human lease is1–300s measured from request issuance, so time spent authenticating consumes its lifetime. `DeviceOwnerHuman` cannot expose a raw `DurableHuman`; expiry and revocation are checked before privilege dispatch. Ordinary sessions and claimed fields never become people. The original embedding-owner attestation API remains a trusted-host boundary; synthetic fixture uses of it do not establish physical acceptance. The OS result proves a local device owner under that OS policy, not a global named identity or consent to arbitrary future jobs. Grant principal labels remain the embedding role, not an OS account lookup.

At most16 leased enrollments and128 bound tasks are retained, with no eviction. New task/admission deadlines and approval expiry must fit the relevant human lease; actual kernel checks independently validate permissions, scope, policy, exact proposal/state binding and budgets. Effects for a task remain tied to its original lease. A fresh human may stop retained work; a new enrollment cannot renew effects whose old task lease expired or was revoked.

Expiry/revocation pauses unfinished affected execution before another native step. This checks the actual FIFO head via an owner-key-gated read-only selector; a paused head conservatively holds later queued work. An earlier valid head cancellation is processed even if a later expired task is queued. The loopback listener remains alive on the typed HumanPaused signal, while actual permission/storage/replay errors still propagate; it does not fabricate Failed/Cancelled or undo confirmed effects. A valid earlier cancellation receipt remains effective despite expiry/revocation, with actual Cancelled/effective-stop observation on the next worker turn. Completed values/results remain readable through an independently authorized ordinary read session. Closed/reopened host instances reject old handles, and recovery clears prior live human authority. Lease/proof metadata is ephemeral; existing EYL/EYLJ formats and historical audit do not restore credentials or safely resume unknown effects.

## Explicit CLI entry points

Plain `eylema start` retains an ordinary session and cannot stop work as a person. `eylema start --human` explicitly opens the OS authentication interface before issuing a scoped stop session of at most5minutes. Cookie/bearer/CSRF credentials expire no later than the human lease. HTTP supplies no human registration endpoint or status flag; it still uses exact loopback Host/Origin/CSRF rules. Browser Stop reports the actual receipt/terminal state, never an inferred rollback. After expiry, fresh enrollment requires a new explicit native start; there is no silent reauthentication.

`eylema human-proof <new-private-directory>` is an explicit physical acceptance command. It refuses existing directories before prompting or changing their files, creates one private native journal, and asks for the fixed counter demonstration. After OS verification it rejects an unapproved two-action proposal, approves its exact binding, applies value2, stops before the remaining value3 action, checks actual partial value/effective-stop evidence, revokes the session and denies its reuse. Reopening preserves the confirmed value/state while requiring fresh human enrollment. Output contains only fixed result metadata; no credentials, raw OS error or private journal body is printed. It is never invoked by repository/native CI. The maintainer must be physically ready; an AI agent must never enter authentication credentials or imitate that person.
