# Project-private local reports (G72)

[Turkish](../tr/local-report.md). The [approved design](g72-local-report-design.md) defines the bounded acceptance target. Implementation and synthetic checks exist; G72 physical/model acceptance is **not_run**. Do not treat these notes as completed autonomous work, language quality, performance or deployment evidence.

The application composes the existing first-party Rust G68 embedding, G30 planning and G57 decision SDKs. Canonical G88 document-claim projections are embedded, G88/G70 returns authorized facts, actual planning proposals enter decision input, and an independent typed verifier compares selected values and citations against source claims. Optional missing evidence, unresolved conflict, abstention and denial remain distinct failures. The final report is a deterministic rendering of verified attributed facts, not open-ended generated prose.

`eylema report run <config.eyl> <new-private-directory>` runs one private job. The closed EYL configuration has five fields: project, task, exactly two language/site/entity/query/prompt sections, bounded source ID/entity/body rows, and nine ordered cached model/tokenizer/config paths. It carries neither approval nor an executable choice. No remote fallback, download or training is provided. Machine paths and synthetic acceptance allocations stay private.

The controller owns terminal input. Real macOS device-owner authentication is separate from explicit source review, prepared-report approval and concrete checkpoint approval. Each terminal acknowledgement binds the displayed digest; model/source content cannot approve anything. A root/lease lasts at most300seconds, authentication60seconds and the model worker180seconds within the remaining root. No session renewal or worker restart is automatic. Planning retains64total/8generation tokens; embedding/decision retain4096context. Unsupported or infeasible inputs stop rather than change these profiles.

A sealed permit requires the actual completed G54 checkpoint, canonical count/source ancestry, G88 observed episode, current source revisions and explicit prepared approval. Final bytes synchronize before the release authority check. Only successful release produces the completion receipt; stop/deadline/authority failure before release retains Partial or OutcomeUnknown and confirmed prior effects. A later stop cannot undo an already released report. Failed/unknown operations are not retried. Interrupted completion is not an exactly-once guarantee.

`eylema report inspect <config.eyl> <job-directory>` opens fresh data and memory stores, reconstructs Need, compares actual memory generation, prepared/final bytes, completion marker and full current citation digests/authorization revisions. It never reconstructs a recovered ToolHost or replays effects. Inspection leaves source/policy/content events and memory bytes unchanged; the existing G63 trusted-clock audit can append clock observations. Withdrawn/expired ancestors and stale generations/revisions reject access.

`eylema report proof <config.eyl> <new-proof-directory>` is the explicitly authorized physical acceptance parent: one positive job, one genuinely stopped job and one fresh proof reader. Its internal `proof-inspect` route deliberately withdraws a cited synthetic source and creates a bounded expiry probe in that new proof directory. This destructive acceptance route is distinct from ordinary inspection and must never be used on ordinary project records. Proof commands have no default automated/CI activation. Original fixed trial/work/read/time ceilings and actual human readiness remain mandatory.
