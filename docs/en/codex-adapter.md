# Bounded Codex development adapter draft

G40 revision 6 adds an owned Rust provider broker in `eylema-development-host`. It is a **draft with incomplete live acceptance**: the corrected installed CLI permission profile passes actual local allowed-read/denied-canary controls. The current source still requires its final full gates, configured provider acceptance and fresh separate review. No completed G40 acceptance is claimed. The maintainer approved the bounded follow-up; the plan records seven used repair cycles, no remaining cycle and a maintainer-approved maximum of five real provider invocations.

The intended explicit tool is Codex CLI 0.162.1, SHA-256 `74c6a6d263f40d65f99c27a815275f5b4ed0bcc2baecc396b4cf3255498bdfc0`, using the existing authorized ChatGPT session and requested `gpt-6.1-sol` / `high`. The installed constructor checks the actual executable hash/version; invocation rejects changed or symlinked executable identity before authentication and rechecks immediately before the model effect. A trusted operator can still replace the pathname between validation and spawn; atomic executable binding or a hostile-operator boundary is not claimed. explicit fixture transport is separately labelled and cannot claim installed-provider evidence. Tool paths, HOME/authentication directory, clock and authority resolver are trusted host inputs, not authentication supplied by model text. A bounded CLI login-status observation and forced ChatGPT login mode refuse missing/API-key authentication before a model reservation; actual status may arrive on stderr. The adapter reads/copies no API key, adds no paid API route or third-party production crate, and exports no operational/training dataset.

A call rechecks the accepted coordinator/workspace binding, reserves a finite deadline allowance before effects and invokes fixed host-owned arguments in a private provider directory outside the task worker's read/write access. Shell, exec, apps, plugins, hooks, browser/computer use, subagents and other interactive capabilities are explicitly disabled. User config/rules are ignored and instruction-document bytes are capped at zero; existing user files are preserved. The proposal schema and curated prompt are the only intended task inputs. The policy uses one inline filesystem table: read-only base, explicit operator/authentication/control/user/volume/temporary-data protected roots and macOS aliases, and the private provider directory as the read exception. Installed invocations require actual local schema-read and protected synthetic-canary denial controls before any provider effect; configuration errors and loader aborts fail these controls. These representative controls do not read real secrets. This trusted credentialed provider broker is separate from the G39 default-deny task sandbox.

Prompt bytes are limited to 16 KiB, CLI retained stdout/stderr to 1 MiB, wall deadlines to 1–60,000 ms, JSON depth to 16 and nodes to 4096. Parsed strings are bounded to 64 KiB. Proposals require one summary and 1–16 unique accepted paths, text up to 32 KiB per change/64 KiB total and explicit deletion semantics; unknown fields, malformed JSON/Unicode/numbers, duplicate keys, escaped/outside paths and nonempty deletion text fail. Outputs are untrusted data and neither apply changes nor authorize commands/PR/merge. Unexpected tool events abort rather than grant a capability. Capture/parsing buffers have bounded overhead in addition to retained-output limits; no disk quota or general security certification is supplied.

The provider's owned process group uses narrow macOS System/libproc SDK bindings. `waitid` with `WNOWAIT` observes leader exit while retaining its PID until group cleanup; callers cannot supply arbitrary PIDs/signals or reap the inner child. A Darwin zombie-only group can return EPERM: bounded inspection of at most 127 listed members must prove all are inactive before reaping; live, unknown, overfull or failed inspection remains an error. Trusted hash/version/login/policy preflights also use this owned-group capture. Regression tests cover an exited leader retaining a pipe and timed-out descendants, in addition to normal exit, live stop and unrelated-process preservation. Unsupported targets fail explicitly. This is a trusted CLI group boundary; privilege-changing or session/group-escaping descendants are not a supported input.

Usage units are admitted CLI deadline milliseconds plus 2,000 cleanup allowance, not money/tokens or hidden backend HTTP request counts. Reported token totals are separate observations. Failed/unknown calls retain their reservation; acknowledgement preserves observed monotonic epochs and primary timeout/cancel/authority/clock/budget causes, without advancing verification/review readiness. Local reaping does not prove remote request cancellation or billing. Quota/model/authentication fixture tests are explicitly synthetic. Actual configured provider acceptance, current CI, separate exact-head review and maintainer/main/guide gates remain required.

Run `cargo test -p eylema-platform --test process_group --locked --offline` and `cargo test -p eylema-development-host --locked --offline` for native/fixture checks. The opt-in `codex-probe --live permissions` driver performs local controls with zero provider requests. `--live success|unavailable|timeout` runs finite real acceptance; `--fixture-observation success|unavailable|timeout` remains synthetic. Unknown modes are rejected before tool/home access. The unavailable probe records the deliberately requested negative model, not the accepted normal model. [Official CLI configuration](https://learn.chatgpt.com/docs/config-file/config-reference) and [instruction discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md) describe the settings; executed local/provider observations remain separate from documentation.
