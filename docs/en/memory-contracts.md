# G87 memory contracts and bounded source context

The portable `eylema_contracts::memory` contracts and native `eylema_host::memory` adapter provide a first memory slice over the accepted [G63 project-data gate](project-data.md). [Memory design](https://github.com/eyleme-dev/devguide/blob/main/docs/en/memory-layer.md) separates working, episodic, semantic, procedural, knowledge_graph and analytical use. These are optional platform capabilities, not six new mandatory models. This adapter resolves **explicit source references**, not semantic similarity, graph traversal or analytical/SQL queries; those remain G70/G88/G89/G90.

An immutable profile binds ID, positive revision, input schema, supported memory kinds/routing roles and backend intent. A source declaration binds actual DataRef, kind/profile/schema, observation/valid-from/expiry, host-attested observed/reviewed/estimated/predicted status, optional declared confidence and embedding-space identity. Semantic sources bind space/model/preprocessing/revision/dimensions by equality. Equal dimensions with different model or preprocessing identity do not match. These fields do not verify inference, calibration, source truth or a physical embedding index.

Only a sealed memory-registry owner and the actual G63 project owner can register immutable source metadata. The backing source must exist, have nonzero put-frame digest, fit the declared retention and not be a training-candidate weight payload. Registration binds the registry to **that live project-store identity**. Another store with identical project IDs, record IDs, bytes and digests cannot substitute for it; after data-store reopen, rebuild/re-register the ephemeral registry with fresh accepted host authority. This is host attestation, not actual human authentication or an automatic fact verifier. A source’s high confidence cannot change its verification status. Predicted/estimated items are labeled and a verified-only request rejects them.

## Query and handoff

A closed eleven-field canonical query carries project/profile/revision, routing role, local purpose, kinds, explicit source IDs, expected embedding space, verified-only filter, byte ceiling and optional token ceiling. Unknown/missing/extra fields, kinds, roles or purposes reject. An appended instruction to grant permissions cannot become a field. Roles are routing selectors, **not proof of caller identity or permissions**. Actual DataSession purpose/scope and all G63 source ancestry govern access.

The adapter checks current data permission before revealing private source status, matches immutable source/profile/schema/space, checks trusted time and reads eligible UTF8 content through G63. It stages the entire canonical EYL context, counts actual serialized bytes including provenance, and rechecks current source use, session and complete data ancestry plus every memory-source TTL against one common final persisted trusted-time observation before returning. No source or session may expire at that observed handoff time. This is a synchronous trusted snapshot, not a promise that bytes remain authorized later. The envelope retains requested role/purpose, project/profile revision, assembly-start timestamp and per-source IDs, put digest, kind/schema/profile, time/status/declared confidence/embedding identity, actual parent references and leaf policy revision. Those labels are not grants; the leaf revision/flags never replace a current ancestor gate.

A cached query stores references and parameters only, with registry identity; it stores no content or authorization receipt. Every reuse rechecks current permissions, source expiry/withdrawal and semantic binding. Withdrawing a source, changing its purpose rights or advancing past source TTL prevents a new context. A cache from another registry is rejected. Bytes already returned cannot be recalled; future tools/providers must reauthorize at their actual handoff. Result `Debug` reports counts only, never context payload. No model prompt or private reasoning is automatically collected into a cache or memory journal.

The selected profile may declare owned_graph/owned_analytical/sqlite_reference/duckdb_reference intent; this prototype returns `BackendUnavailable` for those selections. Only owned_references is implemented. A Rust binding or enum does not install SQLite/DuckDB or approve an engine exception. Query model selection cannot silently cross that boundary.

Token-limited requests return `TokenCounterUnavailable` until actual accepted tokenizer counting exists. `tokens: None` means unknown, not zero or a whitespace estimate. Byte limits still apply. Empty explicit-reference requests return an empty source set after profile/project validation; they do not establish access to any private item or produce a permission grant.

| Admission bound | Limit |
|---|---|
| Profiles / registered sources | 1–128 unique profiles;0–128 unique source IDs |
| Query kinds / routing roles | Up to6 distinct kinds;profile1–9 distinct roles |
| Explicit requested sources | 0–32 distinct IDs |
| Serialized context | 1–65536 bytes, including provenance |
| Staged source bodies | At most32G63 bodies of64KiB each;2MiB before serialization |
| Embedding dimensions / declared confidence | 1–4096 / optional0–10000basis points |

These are structural per-object/operation bounds, not a global allocator peak, latency guarantee or measured token/model throughput. Caller-held object/cache counts remain host budget responsibilities. G63 clock observations can synchronize and consume journal capacity. A source declaration cannot extend backing data expiry; future-valid sources remain unavailable until their trusted time. Registry metadata is ephemeral and rebuilding requires owner authority; no new durable memory/index format is supplied. Existing task/data/wire/journal formats are unchanged.

## Executed evidence

On ARM64 macOS with Rust1.99.0, four new portable tests and fourteen new native adapter tests passed. They exercise all six kind labels, closed query roundtrip/authority-field rejection, missing provenance/time/space and invalid confidence, duplicate/limit failures, same-dimension semantic mismatches, actual purpose-filtered context construction, private status denial, role/purpose/project/foreign-owner/session and profile denial, predictions, source withdrawal/policy changes/TTL/cache identity, advancing clock during assembly, identical alternate backing-store refusal, invalid UTF8, actual serialized overhead, opaque debugging,128profile/source boundaries, explicit empty results and unsupported engines/token budgets.

Test-first failures observed missing modules, then three concrete safety regressions—alternate-store substitution, private-status probing and TTL during assembly—before their fixes passed. Separate review then reproduced two final-sweep expiry failures; regression tests now cover multiple-source expiry and session expiry at a shared handoff timestamp, plus backing-source/ancestry expiry. The native adapter fixtures use owned in-memory storage and controlled clocks; they are **not new physical file, human or model acceptance**. The complete native suite also retains G63’s separately scoped actual file test. Full207Rust tests/47Python, fmt, warnings-denied clippy, native build and selected portable-library Wasm compilation must pass at the final head; PR evidence binds independent review/currentCI/main acceptance. One existing Metal hardware test is ignored by the normal suite and is not required here.

Not run for this slice: new memory-module Wasm execution, actual vector/graph/analytics/SQL engines, tokenizer/inference/training, person authentication, full harness jobs and performance acceptance. Eligibility, correct provenance/nonsecret IDs, truthful host attestation and cooperative storage/clock/hash remain prerequisites. No third-party crate, hidden engine, new provider/model/training/G40 trial or spending is included. Rollback removes this scoped API/registry through review while preserving G63 project journals; derived context is not a migration or new authorization credential.
