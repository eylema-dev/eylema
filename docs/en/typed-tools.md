# G54 typed tools and source-gated execution

[Türkçe](../tr/typed-tools.md). G54 connects a bounded proposed action plan to immutable tool profiles and the accepted [owned executor](deterministic-runtime.md), [oversight](human-oversight.md), [recovery](runtime-recovery.md) and [project-data gate](project-data.md). The portable contracts, runtime registry and native facade are in `eylema_contracts::tool`, `eylema_runtime::tool` and `eylema_host::tool`.

This slice executes two existing first-party Rust operations. It does not install an inference engine, invoke a language model, load arbitrary plugins, run a process or select a database. G39's controlled development host remains a separate boundary; a tool ID cannot route to it. Models may propose arguments and bindings, but profiles, roles and source IDs never mint a session or approval.

## Typed selection

| Owned operation | Input schema | Output schema | Effect |
|---|---|---|---|
| `readTaskValue` | `eyl:empty:v1`: no payload or source argument | `eyl:task-value:v1`: observed canonical unsigned value | Read; no counter mutation |
| `addTaskValue` | `eyl:u64:v1`: canonical unsigned envelope | `eyl:task-value:v1`: observed canonical unsigned value | Checked owned record mutation |

A `ToolProfile` binds a validated semantic ID, positive revision and one closed `OwnedTool` handler. Input/output schema identities and effect semantics derive from that handler; there is no callback registration. An immutable `ToolRegistry` accepts 1–64 distinct profiles. A `ToolPlan` binds the actual task/proposal and 1–8 ordered action bindings. Each `ToolBinding` binds action/profile/revision/input schema/output schema and an optional project-data reference. Its separate canonical eight-field encoding rejects unknown versions, wrong types, extra authority fields and malformed references. Existing task/proposal/wire/journal encodings are unchanged.

Before admission, the registry checks the actual operation/version/effect, profile revision, schemas, native macOS CPU target with no GPU and the exact task-state capability. Reads require an empty argument; updates require exactly the canonical unsigned representation, at most 16 bytes including EYL's seven-byte header. Signed/text/oversized inputs, stale profiles and GPU/browser selections reject. The ordinary executor separately enforces actual scoped permissions, task/policy revisions, budgets, deadlines, checkpoints and idempotency. A routing declaration cannot relax those checks.

## Project-private input and derived output

`ToolHost` exclusively owns a fresh dedicated `DurableHost` and immutable registry. It exposes typed admission and bounded stepping, not the raw mutable host or an unguarded scheduler. It allows one active execution, retains up to 128 immutable execution/provenance entries and never evicts them to admit another action. Use a dedicated private journal and trusted embedding host; do not expose that journal through the legacy console or raw host API as a way around source restrictions.

Literal arguments must already be eligible host inputs. This API does not discover undisclosed provenance or classify secrets. For declared source-backed arguments, the actual G63 `DataSession` must permit Execute on the source and all ancestors. The actual source bytes must equal the proposed canonical argument. The facade binds to the live data-store identity; an equal-looking alternate store or foreign session cannot replace it.

Admission, each effect step, result reads and task-spec discovery recheck **every retained input to that cumulative task value**, including older plans. This conservatively retains restrictions from proposed inputs even if an action later fails. Withdrawing an earlier source cannot be bypassed by a later source-free read or literal action. Source permission, session, ancestry and retention checks use one common persisted G63 snapshot. Each new action's deadline must also fit every retained source and sealed data-session expiry. The original executor checks its own trusted Unix-millisecond timestamp before the actual effect; expiry between source staging and that observation therefore prevents mutation. Truthful compatible clock units and cooperative storage/hash/host services remain prerequisites; this is not hard real-time preemption.

A data denial leaves the active plan blocked with no new effect. It cannot escape into another raw scheduler. A real scoped cancellation receipt can still drive the stop step without reading revoked source bodies; the flag comes only from G11's actual host outcome. For every plan with current or retained source inputs, each action must explicitly require intervention. Omitting that requirement rejects, even when a controller happens to be available. The unchanged G11 checks then require a real capable scoped controller at admission and before every effect, and reserve cancellation event slots. Literal-only plans retain their original optional intervention semantics. Late enrollment does not manufacture reserved capacity. Approval preview/creation and delegated-session revocation forward the actual scoped G11 APIs. Approval covers concrete effect bytes, not project-data rights. Here enrollment is a trusted-host fixture, not real person authentication.

## Results, partial effects and restart boundary

`ToolReport` resolves actual retained effect evidence to owned observations, verifies task/execution/action association and returns canonical counter outputs. Pending, completed, failed, stopped, partial and unknown statuses stay distinct. A failed/cancelled plan with confirmed applied effects is partial; a known prefix does not turn uncertainty into success. Debugging prints status/counts rather than output bytes. Execute on all retained data sources and scoped Read/ObserveEvents are required before results are returned. Training, external disclosure and ecosystem export rights are not implied; this facade supplies no such export API.

A successful step releases the active slot using the trusted scheduler's actual idle flag. Revoking the actor may deny its result read while the executor has already terminalized the plan; that cannot leave the facade permanently latched. A newly authorized scoped reader still needs the original data gates before reading confirmed output. Identical replay returns the same execution and no extra effect. Changed plans/bindings cannot silently rebind provenance; idempotency conflicts remain explicit.

The existing G13 journal retains actual actions, effects and recovery results, but does not persist these new typed source bindings. Accordingly `ToolHost::new` rejects any host with prior command history. Recovered tasks cannot be relabeled as literal inputs or resumed through this facade. `inspect_recovery` returns scoped unknown status and counts of confirmed/unknown effect records, without private numeric outputs or restart authority. Those counts do not resolve the unfinished outcome. Durable typed lineage and skill reattachment require a later separately accepted implementation; this slice is not a restart-capable complete harness. G13's confirmed prefix and unknown outcome stay intact, without automatic replay. Already released bytes cannot be recalled, and journals are not physically erased by source withdrawal.

## Limits and executed evidence

Profiles 64; action bindings 8; active executions 1; retained provenance entries 128. Valid update arguments and each returned unsigned output occupy 16 bytes. A mismatched source read can transiently allocate G63's bounded 64 KiB body before rejection. Historical source checks are bounded by 128×8 references, consume trusted-clock/journal capacity and can be expensive. Original task/event/wire/journal limits still apply. These are structural limits, not a measured allocator peak, latency or throughput claim.

On ARM64 macOS/Rust 1.99.0, three new portable contract tests, three registry tests and nineteen facade tests exercise closed binding shape, missing/duplicate/limit cases, 64/65 profile boundaries, stale schemas/versions/operation/effect/input/targets, actual read/add outputs, denied/stale/oversized requests, idempotency conflict/replay, source policy/withdrawal/TTL/cumulative restrictions, live-store/session identity, source/session deadline binding, actual time advancement between staging and execution, scoped approvals/expiry, effective stops, actor revocation, partial overflow, 128-entry retention and unknown recovery without resumption. Missing-module RED, unsigned-envelope accounting RED, deadline-binding RED and revoked-actor latch RED and the independently reproduced no-controller source-stop RED were observed before their corrections passed.

These new fixtures use owned memory journals and controlled clocks, not new physical IO or real human/model acceptance. The complete suite also retains previously accepted native file/process tests in their own scopes. Full native/Python checks, selected portable Wasm compilation, paired review, pinned integration, genuine separate final-head review and current CI/main proof remain delivery gates. New Wasm execution, generic external tools, actual model inference/training, full harness jobs, real human authentication and performance acceptance are not_run. No third-party crate, provider call, new process/G40 trial, model weight or spending is included. Reviewed rollback removes the facade/contracts while preserving private journals and unresolved outcomes.
