# Local HTTP service — G14

[Türkçe](../tr/local-http.md). Task revision1; [Goal issue16](https://github.com/eylema-dev/eylema/issues/16), following accepted G09–G13.

The owned native `eylema-web` service exposes durable task operations on IPv4 `127.0.0.1`. Its actual macOS socket/file tests create and run a task, inspect the original execution and events, request effective cancellation and reject unauthorized or malformed requests. The public CLI and browser console remain G15/G16; no browser, real person login, remote TLS, GPU or model acceptance is inferred here.

## Composition and authority

The native server owns an opaque `DurableHost` facade supplied by the embedding host. It calls scoped host operations; it receives no mutable runtime or journal handle. Its direct first-party dependencies are contracts, host, journal storage/hash traits, runtime service/grant types and platform entropy. This adapts the proposed component table to the actual native composition; runtime and journal production dependencies still point toward contracts. There is no foreign Cargo package or build script. The portable request codec lives in `eylema-contracts::transport`; importing the native socket service into Wasm is neither required nor supported by the selected portable-library gate.

Only trusted embedding code can register a scoped session or attest a separately verified human. There is no HTTP enrollment, grant, host-key, journal-path, provider or human-status operation. Registration returns a separate bearer and CSRF credential generated by standard macOS entropy. Credentials remain in process memory, have redacted debug formatting and are not written by this adapter to the journal, a URL or a log. The embedding host must protect their delivery; these local credentials do not prove a person's identity. The tests use an explicitly simulated verified-human host fixture.

Every request requires the exact bound `Host`, exact `Origin`, `Authorization: Bearer` credential and matching `X-Eylema-CSRF`. If supplied, `Sec-Fetch-Site` must be `same-origin`. Session expiry is checked before and after body ingress. Permissions and full task scopes are checked by the adapter and the host/runtime. Admission also binds action principals to the enrolled actor. Read/event/evidence requests remain scoped; cancellation requires the actual opaque human session and its permission. Accepted policy, oversight, approval, revocation, budgets and idempotency continue through the durable host. Ordinary task data cannot create authority.

## Closed transport profile

The sole implemented route is `POST /v1/request HTTP/1.1` with one decimal `Content-Length` and `Content-Type: application/eylema`. Each connection carries one request and is closed after the response. This is a deliberately restricted local adapter, not implementation of every proposed API catalogue route or general HTTP/proxy interoperability. Unknown operation tags and payload fields, duplicate case-insensitive headers, invalid/control/non-ASCII header values, query/absolute-form targets, chunked transfer, content encoding and `Expect` are rejected. There is no cross-origin CORS/preflight, TLS, WebSocket, streaming or keep-alive surface. Buffered bytes beyond the declared body are rejected; later arriving bytes cannot become a second operation on the closed connection.

The owned EYL codec encodes requests as `[1, operation_tag, payload]`. Typed task/proposal records are nested bytes using the existing domain codec; the transport adapter does not change their version or authority semantics. Approval IDs are limited to64 and event pages to1–256.

| Tag / request | Authorized operation and success value |
|---|---|
| 0 / `Create` | Create a task with host-configured immutable oversight; `Null` |
| 1 / `Admit` | Admit original typed task/proposal and approval IDs; execution ID |
| 2 / `Task` | Typed current task bytes, value, performed steps, charged steps and charged events |
| 3 / `Execution` | Typed original task/proposal/execution record; identity and original admission context retained |
| 4 / `Events` | Scoped ordered typed events after an optional event ID, bounded page |
| 5 / `Observation` | Evidence/event/task/execution references, timestamp and observed before/after values |
| 6 / `Cancel` | Requested receipt with verified principal/time, or explicit already-terminal state |

Responses are EYL `['ok', value]` or `['error', stable_code]`. Success uses200; admission success is not execution completion. Transport statuses are400 malformed,401 unauthenticated/expired,403 forbidden,405 unsupported,408 ingress timeout,413 size limit,409 known runtime rejection and503 unavailable/configuration/storage. Response headers include `Connection: close`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff` and restrictive `Content-Security-Policy`. Errors never echo request data or credentials.

## Finite limits and failure behavior

| Resource | Default | Accepted configuration range |
|---|---|---|
| Header bytes | 8192 | 128–16384 |
| Header count / name / value | 32 / 96 bytes / 2048 bytes | Fixed |
| Request body | 64KiB | 32 bytes–64KiB |
| Response body | 4MiB | 256 bytes–4MiB |
| Absolute ingress / response-write deadline | 5 seconds each | Positive, at most10 seconds each |
| Session lifetime / retained registrations | 1 hour / 16 | Positive, at most24 hours / 1–16 |
| Native poll interval | 10ms | 1–100ms |
| Rejected-ingress close grace | At most8KiB discarded in5ms | Fixed |

The absolute ingress deadline covers header and body together and is not reset per byte. Accepted connections explicitly use blocking IO with remaining-time socket deadlines; the listener is nonblocking. Interrupted IO retries are finite. Size/authentication/shape checks precede dispatch. Known semantic runtime failures can have durable error records under G13; rejection is not a promise that every failure writes zero journal bytes. Uncertain response delivery does not undo an accepted durable operation: query the known identity or replay the original idempotent admission, rather than invent a new task/execution.

The native polling loop processes at most one connection then one previously authorized queued step. It continues when a client closes; idle polling does not append no-work records. Runtime actions recheck their original scoped authority. A slow connection can delay the next step within the ingress bound. IO deadlines do not establish hard kernel, synchronization, action or cancellation latency. Host/storage failures are explicit and may stop the embedding loop; the owner controls process shutdown. History, sessions and journal capacity remain finite under G13, with no automatic rotation, credential renewal or history deletion.
