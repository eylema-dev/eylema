## Candidate and architecture

Retain the [accepted G27 profile](model-contract.md), [G28 byte loader](weight-loader.md) and [G29 frontend](g29-tokenizer-design.md). The immutable [catalog revision](https://github.com/eyleme-dev/eylema-models/blob/46a5ecda74f4048a17b00cd2c8620a90dcc7626a/catalog/qwen3-0.6b.v1.json) supplies exact provenance and operator identities. Stored BF16 is separate from proposed F32 CPU computation. This is a new bounded execution profile, with its own numerical evidence; equivalence to an upstream BF16/device run is not presumed.

Qwen3-0.6B has28layers, hidden1024, intermediate3072,16query/8KVheads, head128, vocabulary151936, tied embedding/logits and epsilon1e-6. Critically, query projection width is2048, not hidden1024. The accepted local envelope is batch1/context4096/max128newtokens; the upstream40960capacity does not expand it. Defaults remain no bias, no sliding window, default theta1000000RoPE and deterministic greedy decoding. Unsupported quantization, architectures, position schemes, precision or tokenizer profiles reject.

The architecture map must establish every expected embedding, layer norm, Q/K/V/O projection, head norm, gate/up/down projection and final norm, including exact shapes and tied-weight treatment, before constructing a usable session. Missing, extra, misoriented or conflicting tensors reject; a caller-supplied G28 layout alone does not prove completeness. Reuse the same immutable weight snapshot across roles and decode steps, without cloning a full second weight buffer. BF16 expansion is exact bit extension to F32; NaN/infinity reject before entering arithmetic. Convert bounded tiles on demand. F32 arithmetic overflow/nonfinite intermediates reject categorically.

## Preserve reference limits; add explicit execution limits

G23's public4096element/262144work limits and small embedding/head/cache bounds stay intact. They cannot execute full Qwen: head128 exceeds their head-width limit, and the vocabulary and projection extents also exceed it. Raising those caps would erase the accepted bounded reference contract. An external engine conflicts with the owned-Rust direction. Select a separate model-sized executor inside the existing `eylema-model`/`eylema-tensor` paths, with explicit tile/global counters and fallible allocation. Small G23 operators remain cross-checks, rather than being passed larger inputs or mistaken for the whole engine.

Compute matrix rows by fixed ascending input index with separate F32 product/add, no deliberate fused/reassociated reduction initially. Tiling must preserve the full RMS reduction domain and full visible-prefix softmax normalization; never normalize individual tiles and concatenate them. Q/K normalization is per head, followed by half-split RoPE at the absolute position. Query head `a` maps to KV head `a/(Qheads/KVheads)`. Attention uses causal positions, scaled dot products and stable softmax, followed by output projection. Preserve both decoder residuals, SwiGLU, final norm and tied logits. Token-major cached execution must agree with independently computed whole-prefix layer-major execution.

The KV cache belongs to one immutable model/profile/request identity. Append every layer at the same position; a token is committed only after all layers succeed. A failed/cancelled append invalidates the session, so no partly advanced cache can be reused. Reset/new task/role change clears state; no cross-role conversation cache. Batch1 only. EOS completes without another decode step; a generated non-EOS token is fed back at most once. Maximum new tokens, prompt-plus-generation reservation and caller context cap are checked before work; no silent truncation, history loss or context sliding. Equal finite greedy logits choose the smallest original token ID. Output text is untrusted proposal data, with no action authority.

## Roles and a discovered catalog gap

The accepted manifest declares reasoning, planning and specialist intent, **not critic**. G30-P1 explicitly requires critic. A specialist prompt cannot silently count as a critic interface. Proposed coordinated addition: a separate CPU candidate manifest/receipt in `eylema-models`, with a model-package native fixture, retaining the old G27 manifest unchanged. Bind all four exact role interfaces and their bounded text/structured-evidence adapters; preserve critic input/output units and proposal semantics. The later concrete plan must freeze adapter schemas, reject malformed outputs and show four actual distinct role outputs. Registration does not establish critic or other domain quality.

That catalog/guide linked scope is a proposed extension requiring the owner's actual decision before changes. Current preparation writes only this paired design and translation fingerprints. No shared schema, generic `check_assignment` behavior, root Cargo, workflow or new crate changes are proposed. Generic metadata assignment remains `UnsupportedLocal`; only a separately validated owned-CPU session can issue an execution receipt. That receipt must identify the admitted role/profile, artifact/tokenizer, numeric limits and actual outcome, and must never be interpreted as authority or a global support upgrade. Unsupported roles/backends fail without an external fallback. Later router/harness integration remains separately gated.

## Memory, work and cancellation

Plan from actual stored artifact size, immutable tokenizer storage, per-layer KV, live activations/tile conversion and bookkeeping. For F32 KV, bytes=`2*layers*KVheads*head_dim*context*4`; this candidate requires229376bytes per cached position:14MiB at64positions or896MiB at4096. These are arithmetic allocations, not measured RSS, throughput or a fit recommendation. Do not duplicate tied weights, count each role as another model copy, or double-count unified physical memory.

Proposed first native acceptance envelope: at most64total positions and8newtokens per job, within the larger manifest ceiling; full4096position execution remains unmeasured. Exercise exact smaller-envelope boundaries and separately validate4096/128manifest arithmetic without claiming that full workload ran. A concrete plan must bind aggregate reader/storage limits, global resident/work counters, checks before known allocations/reads, token/layer/tile cancellation points and a wall deadline. A proposed2560MiB logical-content ceiling includes the1503300328byte immutable artifact, tokenizer allowance and cache/workspace; actual allocator/OS/other-job memory remains measured separately and may still reject the workload. No automatic claim that it fits this Mac.

The library opens no files or network connections. Reader blocking deadlines remain caller responsibilities inherited from G28. For computation, bounded tiles check cancellation/deadline/work limits before and during progress, including logits and prompt preprocessing; a prompt or projection cannot bypass stop checks. No accepted partial proposal after cancellation. Effective mid-computation stop must be demonstrated on native execution, not only with a pre-cancelled flag. Capacity or deadline failure is an explicit failed acceptance, not permission to weaken a gate.

## Numerical evaluation and acceptance stages

The authorized development-only trial freezes three synthetic configurations before the candidate: unequal hidden/query extents, grouped heads, one/two layers,2/4/128head widths, nonzero positions, nonsymmetric weights and tied logits. A Decimal80 batch/layer-major oracle with its own Taylor trigonometry precedes an independently scheduled F32 token-major Rust candidate. Frozen threshold is `abs_error <= 0.00005 + 0.00005*abs_reference`, with finite values, exact shapes and greedy IDs. The private trial covers1218scalar comparisons plus cache-prefix invariance, BF16 sentinel/negative tests, malformed dimensions/context, pre-cancellation and ties. Four runtime semantic fault injections exercise grouping, half-rotation, cache loss and logit orientation. These are not compiled production-source mutants or real-model reference vectors. Full resource/cancellation safety is not established by the trial.
