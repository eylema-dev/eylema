# Controlled development workspace

G39 adds the first-party `eylema-development-host` native host to the accepted G38 coordinator. `Workspace::create` requires an implementing coordinator with current host-resolved authority and an accepted immutable base. The source checkout HEAD must match that base. NeedSpec fields, constructor values and authorization references are data, not authentication; a trusted identity/policy host must supply the authority resolver. The native proof uses an explicitly synthetic resolver, while filesystem, Git and process effects execute on the actual Mac. No provider or GitHub call occurs.

The host creates a detached worktree in a private control root, with a task-key/revision binding and separate scratch directory. It never resets, cleans, stages or commits the caller checkout. Tests retain staged, unstaged and untracked caller canaries byte-for-byte. A retry for the same task returns `AlreadyExists`, preserving earlier changes and incomplete setup for explicit reconciliation. Source/base mismatch, nonregular tracked entries, submodules, symlinks and configured checkout filters fail. Git/control metadata remain outside worker read access. System Git is a trusted platform input; hooks, fsmonitor, global/system config and attributes are disabled, filters are rejected, and each Git capture has a 20-second deadline, 4 MiB stdout and 64 KiB stderr cap.

`run_single` invokes a trusted executable outside the worktree/scratch through the available macOS `sandbox-exec`. This deprecated OS facility is an explicit experimental dependency; missing or denied sandbox support fails closed, with no unrestricted fallback. The profile denies by default, permits reading the checked-out source, scratch, executable and named system loader resources, and permits writes only to accepted file/directory scopes and scratch. Worktree `.git` access, hardlink creation, network, IPC, keychain access, process fork and foreign process signals are denied. Metadata reads needed by the loader remain permitted; these tested boundaries are not a universal security certification. Write access has no disk quota: wall/output limits and post-run artifact limits do not bound total on-disk worker writes. The trusted host must provision and monitor storage separately. Arguments and scope must not contain host credentials. A fixed cleared environment contains only HOME/TMPDIR for private scratch, PATH and LANG; stdin is null.

Worker wall time is bounded to 1–60,000 ms, combined retained stdout/stderr to 1–1,048,576 bytes, and arguments to 64 entries of at most 4,096 bytes each. The host polls cancellation, output overflow, deadline and current coordinator authority. Results distinguish worker deadline/cancellation/output limits from authority denial and retain the exact coordinator error for task budget, clock, binding or state failures. Revocation or clock/state failure stops and reaps the exact owned child. The cancellation API exposes an owned flag, not an arbitrary PID. Fork denial prevents task descendants retaining pipes. Task stdout/stderr remain untrusted private data and must not be treated as control instructions or published without review.

After the owned child is reaped, `artifacts` checks the unchanged base, all tracked and untracked changes, path scope, regular files, symlink/hardlink rejection, UTF-8, file count and byte limits. Limits allow 1–128 changed files and 1 byte–16 MiB of retained text; traversal is capped at 100,000 entries. Each artifact carries `path`, `text` and `deleted`; a deletion is distinct from an empty replacement. Failed/cancelled/timed-out work and control metadata remain available for explicit trusted-host reconciliation. This API exports observations; it neither applies edits to the caller nor authorizes a commit, PR, merge or release.

Run `cargo test -p eylema-development-host --locked --offline` for actual worktree/sandbox/process tests, then `cargo run -p eylema-development-host --bin workspace-probe --locked --offline` for a sanitized native summary. The proof worker is first-party Rust with test-only minimal macOS fork/signal probes; those platform calls are explicit. Tests cover dirty caller preservation, scoped writes, secret-canary/environment/Git/sibling denials, symlink and hardlink escape, network/fork/signal denial, output bounds, timeout/cancel/revocation, stale base, retry preservation and empty/deleted artifacts. Trusted-host command tests exercise finite output and deadline rejection. Full repository and unchanged native Rust/selected-Wasm gates remain separate checks. The native host is not compiled as Wasm; portable coordinator compilation does not prove browser execution. Compiler/provider calls, token costs and live GitHub delivery are later Goals, not results of this proof.
