## Implemented flow

`eylema_runtime::routing` validates bounded immutable route/model declarations, compares exact integer utility units and calls the existing G80 resource estimator. The native `eylema_host::routing::Router` binds registration to the actual sealed project owner and original live ProjectStore. Caller strings, pure selection values and estimate reports grant no authority.

Catalog→describe→select→call consumes explicit IDs/revisions and current Execute-authorized sources. Description includes schema, source kind/put digest/revision/expiry/purpose and bounded content. Known source lengths are authorized without copying bodies before the aggregate32768byte read bound; the encoded description is capped at16384bytes including provenance. Skill decoding has a narrow preflight before the general EYL decoder:4096bytes,256nodes,depth8,list16, no maps. Only existing closed G75 native-counter packages are supported; reference text is data, not instructions.

Opaque transient selection tickets bind original registry/store identities, retained data session, complete canonical request and actual query or ToolPlan/SkillLoop/approvals. Every query vector bit, representation/generation, ordered reference, task/action/schema/approval and skill version participates. Calls reauthorize current sources/ancestry/session and immutable resource/profile validity before actual G70 search or unchanged ToolHost skill admission. Reopen/another equal-looking store cannot reuse the handle. No router journal, automatic retry, model download, external fallback or new authority injection API is supplied.

Skill routing additionally requires every private selection/description control to be the executed package or one of its transitive ancestors. Existing G75/G54 per-effect/result checks then retain that influence. Nonancestor controls and action deadlines beyond source/session/registry/policy/quality/capacity validity reject before admission. `SkillAdmitted` is not a completed job; actual stepping, reporting and scoped cancellation remain existing ToolHost operations. A final handoff failure after admission returns `AdmissionOutcomeUnknown` without a private receipt, not an assertion that admission was rolled back. Existing journal and source-gated inspection behavior remain; no new routed recovery/list API is claimed.

## Selection and resource boundaries

Utility0..1000000 is declared and uncalibrated. The initial floor is500000 and the minimum next-eligible margin100000; ties, smaller margins and unknown/contradictory declared grounding abstain. Typed code/document specialists or model-executing skills without an implemented accepted handler are unavailable. The router neither infers a free-text intent nor executes a model to create these assessments. Source truth and semantic contradictions are not automatically verified.

Resource views borrow immutable owner-registered G80 snapshots. Identity, parameter/backend/artifact/context, overlap and freshness checks reuse the unchanged estimator. G74 tightens its view to2pools/4residents/8invocations/8auxiliaries/4overlap groups/16members. Estimated fit is planning-only, not observed capacity, latency, quality or execution permission. Missing coefficients, stale/mismatched declarations, infeasible overlap and unsupported formulas cannot qualify selection. Declared context+response is checked; a request for verified token counting is unavailable. No word/byte count is relabeled tokens.

Per synchronous operation:10000000work units,64MiB logical router-owned transient reservation and at most5seconds cooperative deadline. Router preparation and its actual G70 child share the same Control/token/deadline; no child reset occurs. Caller may explicitly create a new bounded control for a later operation. Reusing one control across selection plus a full four-source call accumulates work and can reject: the observed combined test reached9931403units and returned Limit before exceeding10million. A positive call separately compares its actual charged work against a direct child baseline, requiring more than2million additional wrapper units. These units are declared accounting, not CPU instructions or a benchmark. Caller-held state, allocator slack and OS/RSS/native blocking remain separate; timeouts are cooperative.

G70 ranks zero-score lexical candidates. For the G74 pure lexical route, no positive term-overlap score produces a separate `NoMatch` and no irrelevant candidate bodies. This is an explicit router admission policy over the unchanged G70 result, not a claim that G70 returned zero raw hits or that semantic relevance was evaluated. Vector/hybrid routes keep existing rankings. A synonym with no shared normalized term can be NoMatch; broad relevance and grounded answer quality remain later acceptance.
