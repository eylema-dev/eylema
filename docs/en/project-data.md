# G63 project-private data and purpose gates

The owned `eylema_contracts::project_data` types and `eylema_host::project_data::ProjectStore` add a separate project episode/artifact journal. This is a data-use foundation for the [memory layer](https://github.com/eyleme-dev/devguide/blob/main/docs/en/memory-layer.md), tools and learning. It does not retrofit project isolation into the older single-user task console or implement RAG/knowledge-graph/model storage engines. G54/G55/G64/G87–G90 must consume the gate in their accepted scope.

A logical `DataRef` binds ProjectId and DataId. IDs follow the bounded ASCII ResourceId contract; values such as `..` remain opaque IDs and are never joined to filesystem paths. Every live store returns a sealed owner identity; only that owner enrolls or revokes purpose/ID-scoped sessions, changes policy and withdraws items. Same-looking project/item IDs in another store do not reproduce those capabilities. Owner bootstrap is trusted host configuration, **not actual person authentication**, which remains G73. Request/model outputs cannot create owner tokens.

`execute`, `collect`, `train`, `external_disclosure` and `ecosystem_export` are independent purposes. Sessions and new records default to no purpose rights; egress review defaults false. Collection requires scoped collector authority, eligible content and collect permission for all declared source ancestry. Only the owner assigns each record's declared permissions and explicit egress-review attestation, with exact positive policy revision; a failed revision cannot overwrite a later policy. That attestation is not a fabricated human review.

Derived data and training-candidate records require immutable existing same-project parents. Every use rechecks all source policies, expiry and terminal withdrawal through a bounded visited-set traversal. A child permission or review flag cannot widen an ancestor. `DataMetadata.permissions` and `reviewed_egress` describe the **leaf's declared policy**, not effective inherited permission, public classification or authority; consumers must call the current gate. Parent provenance is retained and egress is denied if any ancestor remains unreviewed/private. Withdrawing a source blocks future descendant use, including a trained-candidate reference; this does not unlearn weights or recall already copied data. Payload and kind are immutable after collection; successful policy changes/withdrawals are synchronized before acknowledgement.

Local `read` accepts only execute/collect/train. `export_manifest` accepts only external disclosure/ecosystem export and returns a closed projection of nonsecret IDs, source references, kind, put-frame digest, revision and expiry. It has no arbitrary payload, prompt, explanation or credential field. Actual record-body publication/provider handoff remains later work. Episode/artifact/derived/training_candidate are the only kinds; unknown, raw_reasoning and credentials kind names are rejected. Arbitrary caller payload bytes are **not automatically classified or scrubbed**; eligible content, nonsecret IDs and accurate lineage are trusted ingestion prerequisites. A caller cannot use this API as proof that copied content is licensed, secret-free or truthfully attributed.

## Persistence, time and failure

Existing task contract and EYL/EYLJ v1 stay unchanged. A separate `project-data` payload tag/version1 binds the expected project and initial trusted timestamp. Canonical put, policy, withdrawal and strictly increasing clock records replay with exact schema, kind, revision, lineage and limits. Expected-project mismatch or unknown/malformed/unsupported events fail. The digest retained for an item is its synchronized put-frame journal digest, not a fresh standalone payload hash. Reopen preserves payload/metadata/policy/withdrawals and supplies fresh owner identity; old sessions are invalid even when their slots and IDs look equal.

The host supplies a trusted Unix-millisecond clock. Caller timestamps cannot replace it. Clock unavailability or regression denies access. When time advances, a synchronized clock watermark is written **before returning data**, including before an expiry rejection, so reopening with an older clock cannot resurrect observed expired records. Reads can therefore require IO and consume journal budget; this initial correctness profile is not a throughput claim. Expired/revoked sessions deny, terminal record withdrawal cannot be undone, and expiry cannot be extended by changing policy.

`project_journal_limits()` sets a maximum4096 frames,70 KiB canonical frame payload and64 MiB journal. The read-only `Journal::limits()` accessor lets the store reject more permissive supplied profiles. Stricter journals may exhaust sooner and fail explicitly. The trusted caller must construct the journal using the accepted profile before passing it; generic journal creation/open has its own validation/allocation bounds. ProjectStore does not claim to constrain a privileged caller's earlier generic IO.

| Bound | Ceiling |
|---|---|
| Items and retained payload | 1024 items;8 MiB total |
| Item payload | Nonempty, at most64 KiB |
| Sources / lineage | 16 unique parents;depth32 |
| Sessions / scope | 64 slots per live store;64 unique IDs per session |
| Expiry | Future, at most365days;child no later than any parent |
| Journal | 4096 frames;70 KiB frame payload;64 MiB file |

These are admission/format bounds, not measured allocator peak, hard filesystem deadlines or SSD capacity. Withdrawal/expiry deny logical use but retained append-only payload/history remains on disk and in recovery state; no compaction, backup purge, encryption or physical erasure is provided. Bytes already read cannot be recalled. Future caches/indexes/provider handoffs must reauthorize source references at the actual handoff, never reuse a metadata flag or old manifest as a grant.

Journal hash, locked storage and clock are trusted host services. Native files use host-selected paths inside an owner-controlled directory, mode0600 creation, cooperative exclusive locks and actual file/parent/full synchronization. A write/synchronization uncertainty gives no success receipt and poisons later access; explicit inspected reopen and fresh enrollment are required. Fully written uncertain bytes may be found on reopen; parsing cannot retroactively prove acknowledgement. These boundaries do not defeat hostile same-user processes or authenticate externally rewritten journals. Unsupported/native service failures stay explicit; no weaker fallback is introduced.

## Executed evidence and limits

On ARM64 macOS with pinned Rust1.99.0, the test-first host suite failed on the missing project-data modules, then passed after implementation. Twelve behavioral tests cover each independent purpose/default denial, no payload egress, private ancestry, scoped/foreign owner/session and equal-looking project IDs, cross-project collection/read/parents, live multi-parent/candidate inheritance, terminal withdrawal, expiry and persisted clock rollback, unavailable clock, policy revision conflicts, malformed replay, IO uncertainty/poisoning, exact metadata/payload reopen,64 KiB/8 MiB/1024item/16parent/32depth/64scope/64session bounds, permissive journal rejection and explicit exhaustion.

One additional **actual native file test** creates two private temporary project files, checks0700directory/0600file modes and cooperative lock conflict, uses real SystemTime and CommonCrypto/full-sync bindings, closes/reopens exact metadata/body/policy, rejects wrong expected project and stale/foreign live sessions, and proves terminal withdrawal survives reopen. Logical `..` project identity never becomes a path. Data is synthetic; the temporary directory is removed. Injected IO/clock failures are fixtures, not physical disk/clock faults.

Complete native fmt/clippy/tests/build and selected portable-library Wasm compilation plus AGENTS Python/repository/PR/diff gates are required; final PR evidence records revision/counts and genuine separate review. New project-data Wasm execution, real human enrollment, malicious-OS isolation, physical crash/erasure, actual RAG/graph recall, model inference/training and complete harness jobs remain not_run. Rollback removes this scoped API through a reviewed PR; preserve existing project journals and diagnose version compatibility rather than treating them as old task journals.

The separate review required additional known-event replay coverage:26 malformed put/policy/withdraw/clock events and4 malformed configurations reject;4 valid event controls reopen. This adds tests for existing guards without changing production behavior or claiming a reproduced production defect.
