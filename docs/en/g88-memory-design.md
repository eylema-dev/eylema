# G88 durable episodic, semantic and graph memory design

Status: owner-approved specification; implementation and native acceptance are under verification. See [current behavior and evidence](memory-store.md). [Issue 94](https://github.com/eyleme-dev/eyleme/issues/94), proposed card revision 4. [Türkçe](../tr/g88-memory-design.md).

The maintainer means a knowledge-graph pattern by CortexDB, not a selected database. Stable memory semantics must survive model replacement. That decision does not approve this specification, a future implementation plan, production code or new model/artifact calls. Source base is `a3b06ab698d338b893714b1cfcad850f4dfaa35f`; guide base is `25db00b5c20a6acc592d1df4d5eade0b725c5f28`. Accepted dependencies remain G87, G70 and G50.

[G70](retrieval.md) supplies owned lexical/vector/hybrid algorithms. [G50](decision-evidence.md) supplies scoped actual tool outcomes. Reusing these does not prove G88 persistence, graph joins or memory-assisted jobs.

Add portable types under `eylema-contracts::memory` and a separate native companion under `eylema-host::memory_store`; keep the G87 registry API and behavior. Use existing Journal, ProjectStore and G70 interfaces. No new crate/root Cargo registration, production dependency, SQL engine, inference engine, task/data/wire-format migration or permission-policy change. A separate memory crate would improve packaging isolation but requires additional Cargo scope without a present consumer need. SQLite/DuckDB interchange remains G90.

## 2. Typed records and knowledge eligibility

Closed, versioned records represent episodes, entities, attributed facts and typed entity relations. Every record binds project, logical ID/content revision, profile/schema revision, exact source references and put digests, observation/valid-from/expiry times, bounded typed content and optional declared confidence. Facts name subject/predicate/typed object; relations name two entity IDs and a predicate. Entities and endpoints are project-local. Dangling endpoints, duplicate identities, invalid intervals, incompatible representation bindings and unchecked count/byte overflow reject.

Keep assertion origin (`observation`, `document_claim`, `estimate`, `prediction`) separate from admission state (`proposed`, `explicitly_reviewed`, `verified_outcome`). A review cannot erase prediction/estimate origin or turn a forecast into an observation. Default reusable-knowledge queries admit explicitly reviewed document claims and genuine verified observations; estimates/predictions remain labeled and excluded. An explicit non-knowledge evidence query may include them with their original status. Later verified outcomes create a new attributed revision linked to the old prediction, not a rewritten history. Confidence and repeated agreement never promote knowledge.

Proposal writes require current Collect authority. Explicit review requires the sealed memory owner, exact expected generation/revision and pinned review-source provenance. This is trusted host-owner attestation, not proof of a new real-person login or source truth. Observed episodes are obtained from the actual ToolHost using its scoped session/execution, not caller-built ToolReport/DecisionEvidence fields. A narrow crate-private bridge may expose sealed actual outcome plus the complete retained source-control set; it must call existing report authorization and not change tool admission/stepping semantics. Memory persistence separately rechecks Collect on every influence. Unsupported or over-limit provenance rejects rather than dropping parents. Failed/partial/stopped/unknown outcomes retain their real status and never become completed success.

All source influences, including review and actual tool controls, must be parents/ancestors of the immutable G63 text projection used for recall. A record has at most 8 direct source influences, within G63's stricter existing lineage rules. New review/content revisions create new projections when lineage changes. No raw conversation, private reasoning or credential schema field is introduced; arbitrary supplied text is not automatically certified secret-free.

## 3. Durable writes, replay and explicit outcomes

The memory facade owns a separate EYLJ journal with a versioned header and atomic single-event generations. Events cover record revisions, explicit reviews and logical deletion. Compare expected global generation and record revision before side effects. Preserve old revisions/conflicts in history; never silently overwrite a concurrent writer. Sealed owners/sessions bind the original live project-store and memory-store identities. Fresh reopen requires fresh host capabilities; an equal-looking store or an old cached handle cannot substitute.

The G63 projection is an immutable Derived record with deterministic bounded UTF8 text and every influence in its ancestry. Its actual DataRef, digest and permission/retention bounds are recorded in the memory event. Prepare/synchronize the projection first, then append/synchronize the canonical memory event. A successful write receipt names the synchronized memory generation, record revision and journal digest, after a final current-authority check. A crash between these steps may leave an orphan projection; uncommitted projections are not discoverable through the memory facade. There is no multi-file transaction or automatic permission grant. Existing G63 owner policy operations remain explicit.

Write/flush/sync uncertainty poisons the writer and returns `WriteOutcomeUnknown`/`NeedsReopen`, never a success acknowledgement or an asserted rollback. A failure after a synchronized commit but before final authorized receipt likewise reports unknown without private output. Reopen inspects committed state; it does not automatically replay effects or retry writes. Duplicate/stale generations and malformed canonical events reject. Deletion is a synchronized tombstone plus current source exclusion; append-only history/backups remain, so physical erasure, encryption and hostile same-user filesystem isolation are not claimed.

Use unchanged Journal framing/digests. A bounded storage/payload guard must validate the closed memory envelope before general payload decoding: 8 KiB/frame, at most 256 value nodes, depth 8, list length 32 and no maps. It rejects hostile declared extents before allocation/scanning, observes a finite read/seek/byte allowance, and checks cancellation/deadline before/after opaque IO. Do not weaken the shared EYL/EYLJ codec or copy an external implementation. Digest-valid but invalid memory schemas, wrong project/profile, dangling relations, inconsistent generations and truncated/changed files fail closed. Journal integrity is not source consent. Opening this owned journal is a privileged trusted-host replay boundary, not approval of an imported/foreign journal; no untrusted import can acquire reviewed status through replay.

## 4. Current-authority recall and graph composition

A closed query binds project/profile/generation, role, local purpose, kind/origin/knowledge filters, effective time, explicit entity/predicate filters, optional graph seeds/hop ceiling, representation identity, lexical/vector/hybrid input and output/work/byte limits. Role is a routing selector, not caller identity. Historical effective time never bypasses current source withdrawal, session expiry or ancestry policy. Unknown token-count requests remain unavailable; bytes are not renamed tokens.

Authorize the query/live identities first. Filter source rights, current lineage, review/origin, validity and typed join predicates before traversing eligible graph edges or ranking. Graph expansion visits only eligible entities/relations with a bounded visited set; cycles cannot evade hop/work ceilings. No private excluded-record counts/status are exposed. Explicit absent and unauthorized seed/source probes use the same public authority error; an authorized broad query with no eligible evidence returns Empty. At result handoff recheck every used source, digest, source/record TTL and session/ancestor permission at one common persisted trusted-time observation.

Build a temporary G70 Snapshot from the currently authorized candidate projections, using their actual G63 bytes/digests and immutable representation binding. Call unchanged G70 build/search/encoding algorithms with the same operation Control. This permits graph/knowledge filters before ranking without changing G70's engine or teaching its host adapter a new predicate API. The durable memory records/vectors are authoritative; lexical/vector indexes are rebuildable views, not a second durable transaction. More than 16 eligible indexed projections for a requested exact view returns a limit/unsupported result, not silent omission. Graph-only queries need no vector ranking. Vector provenance remains caller/fixture supplied unless separately established by actual inference; matching a model ID is not proof it produced a vector.

Graph-only order is minimum hop then stable record ID/revision. For lexical/vector/hybrid queries, apply the optional graph restriction first and retain G70's existing score/tie semantics on the filtered projection set. Deterministic deduplication retains all source references and statuses. Predicate profiles declare single-value versus set-valued semantics: different values for a single-valued subject/predicate with overlapping validity yield an attributed conflict group. Preserve both claims; neither newest timestamp nor higher confidence silently wins. Non-overlapping historical values are not a current conflict. General natural-language contradiction detection is not supplied.

If a selected conflict group cannot fit the hit/byte limit, return an explicit incomplete-conflict/limit outcome with no settled single answer. Distinguish Empty/NoEvidence, Forbidden, Conflict, IncompatibleProfile, NeedsReopen, Limit, Cancelled and Deadline; a backend failure is not an empty successful search. Cached queries retain references/generation/store identity only; each reuse rebuilds and reauthorizes. Withdrawal/delete/expiry must exclude affected graph, vector, lexical and cached recall even after native reopen. Existing returned bytes cannot be recalled.

## 5. Finite profile and resource accounting

| Bound | G88 initial profile |
|---|---|
| Current records / entities / relations | 128 total records; at most 64 entities and 128 relations within that shared total |
| Record revisions and journal | At most 512 frames including header; 8 KiB encoded payload/frame; 2 MiB total file including framing |
| IDs / typed literal / projection | Existing IDs at most 128 bytes; literal at most 256 bytes; actual UTF8 projection at most 1024 bytes |
| Provenance / graph | At most 8 influences/record; 8 seeds; 4 hops; 128 unique visited records |
| Indexed recall | At most 16 eligible projections, one G70 chunk each; 1024 dimensions for the first declared representation profile |
| Context | At most 32 returned sources/hits; at most 65536 encoded bytes including citations/status/conflict metadata |
| Synchronous operation | At most 100000000 shared work units, 64 MiB logical transient reservation and 5 seconds cooperative deadline |

These are independent ceilings, not a promise that all maxima fit simultaneously. Existing stricter G63/G70 checks still apply. Preflight all shapes/byte extents and checked sums before cloning, hashing, comparison or generic decoding. Charge visited/copied/hashed/encoded bytes and bounded metadata/lineage calls before work. Guarded journal replay uses a conservative full-operation escrow for at most 2 MiB and 512 bounded frames; native read/seek ceilings and shared Control consumption must be explicit in the implementation plan. A request whose escrow does not fit rejects before IO. The same Control covers memory filtering/traversal and its actual G70 child; never reset or secretly replace it. Reserve at most 8 MiB for this facade’s retained state at operation entry in addition to transient escrows; reject if it does not fit. Per-operation limits do not count caller-held ProjectStore/ToolHost state or physical RSS/OS buffers. IO deadlines are cooperative and checked after native calls.

For the owned memory journal, reopen admits at most two scans, 4 MiB aggregate reads, 4096 read calls, 16 seeks and 16 metadata calls; it performs no writes or sync. A record append admits at most 8276 written bytes (8 KiB payload plus 76-byte frame plus a conservative 8-byte header allowance), 1024 write calls, 4 seeks, 4 metadata calls, one flush and one synchronize. Creation permits the fixed header plus first memory-header event and at most two flush/synchronize pairs. Exceeding these caps fails even for a fragmenting trusted Storage. Before replay, reserve 48 MiB and charge `12 × admitted_read_bytes + 4 × 512 × 256 × 2` units; this covers the two admitted scans and bounded decode/event work, and rejects underfunded requests before the first read. Record/query-specific byte, comparison and metadata escrows are added before those operations; they cannot consume a second hidden Control. G63/ToolHost opaque operations retain their own accepted bounds and require a finite precharged per-call allowance; this journal IO tally does not pretend to instrument their internal physical IO.

The underlying G70 Control already permits at most 100 million work units/64 MiB/30 seconds; this facade tightens time to 5 seconds. G74's separate 10-million/5-second route ceiling remains unchanged: G88 does not automatically add a new router handler or widen its budget. G72 must bind any consuming loop explicitly. No performance, measured capacity or tokenizer/model-throughput claim follows from these constants.

## 6. Native and held-out acceptance

Freeze inputs, reference digests, query/answer/citation sets and bounds in the concrete plan before production. G88-A1/H1 require real owned native files with 0700 directories/0600 files, actual synchronization and lock refusal, write/close/reopen in fresh child processes and fresh capabilities. At most two bounded child phases (writer and reopened reader), each at most 10 seconds/4 KiB diagnostic output, using only a private synthetic test directory. Controlled trusted clocks may make temporal cases deterministic; physical IO remains real, not an in-memory substitute. Add fault-storage write/flush/sync and partial-frame/unknown-outcome tests; do not claim power-loss testing.

Eight held-out EN/TR document evidence-brief jobs use the same deterministic citation renderer/verifier for flat RAG and memory-enabled recall. They complete a real native consuming flow, not only API constructors. They are evidence-collection/document-brief tasks, not generated-language quality or the model-backed G72 acceptance. Freeze equal query budgets/corpus/representation bindings, report both conditions' actual outcomes and work/bytes, and require no unauthorized citation. Do not require or invent a baseline loss or claim general superiority.

The frozen family contains EN Pump A/Site North/owner Mira/checklist C7 and TR Pompa B/Güney/sorumlu Ece/liste C9 source documents, plus attributed overlapping owner claims, expired claims, an excluded prediction and irrelevant/cross-project decoys. Jobs cover direct EN/TR ownership, two-hop site→equipment→owner/checklist evidence, EN/TR conflict without a settled owner, historical/current validity and prediction-only NoEvidence. Their exact source strings and expected IDs/statuses are fixed independently in the plan. Memory-enabled results must satisfy all eight literal brief/citation expectations; report flat-RAG results under identical bounds even if equal. Raw source text, reviewed claims and observed outcomes retain distinct labels. Synthetic vectors prove composition, not embedding-language quality.

Negative coverage must include stale writers, wrong owner/store/session/project/purpose, attempted self-promotion, fake tool outcomes, incomplete ancestry, changed source digests/revisions, future/expired records, high-confidence prediction exclusion, conflicting single-valued versus valid set-valued relations, cycles/dangling endpoints, join filtering before ranking, cross-scope tie probes, revoked/deleted source through cached and reopened views, representation mismatch, exact encoded-overhead/count boundaries, cancellation/deadline during traversal/ranking/replay and no partial result at the final sweep. A model saying “saved” is never persistence evidence.
